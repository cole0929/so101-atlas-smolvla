## 项目 A：轨迹可视化与数字孪生

### A0. 为什么要做这个项目

**问题**：机械臂在物理空间运动，人眼看不到它「走过哪些路径」。如果能让电脑实时画出末端轨迹，就能：
1. 验证机械臂运动是否符合预期（安全监测）；
2. 记录示教轨迹（后续可复现/学习）；
3. 统计运动质量（速度、平滑度、重复精度）。

**学习目标**：掌握 ROS2 的基本数据流（话题发布/订阅、TF 坐标树、RViz 可视化），这是后续所有机器人开发的地基。

### A1. 系统架构：数据从哪里来，到哪里去

```dsh-ui
{"title":"轨迹可视化数据流","gap":10,"items":[{"type":"mermaid","code":"graph LR\n    A[板端串口读从臂关节] -->|UDP 15000| B[so101_joint_bridge]\n    B -->|/joint_states 话题| C{Zenoh 网络<br/>跨机器传输}\n    C --> D[WSL retime 重打时间戳]\n    D -->|/joint_states_local| E[robot_state_publisher]\n    E -->|/tf 坐标树| F[recorder 查末端位姿]\n    F -->|/ee_path /ee_trail| G[RViz 显示轨迹]"}]}]}
```

**为什么要分这么多步？每一步解决什么问题？**

| 环节 | 解决的问题 | 学到什么 |
|---|---|---|
| 板端串口读关节 | 机械臂是串口设备，需要程序读取六个舵机角度 | 串口通信、电机总线（STS3215） |
| UDP 15000 转发 | 板端程序间解耦，读关节的程序和控制程序分开 | 进程间通信、单一职责 |
| `/joint_states` 话题 | ROS2 的标准关节状态消息格式 | ROS2 话题模型（发布/订阅） |
| Zenoh 跨机传输 | 板端(ARM)和 PC(WSL)物理分离，需网络桥接 | 分布式系统、中间件选型 |
| retime 重打时间戳 | 板端时钟不准，直接发会导致 TF 抖动 | 时间戳在机器人系统中的重要性 |
| robot_state_publisher | 关节角 → 各连杆坐标变换(TF) | 运动学正向解（FK）的 ROS 实现 |
| recorder 节点 | 订阅 TF 查末端位置，累积成轨迹 | 坐标变换查询、轨迹数据结构 |

**学习要点（为什么 retime 存在）**：机器人的关节状态是「带时间戳的」。板端时钟没同步（差 18 天），如果直接用板端时间戳，PC 端 TF 会认为数据过期/未来而拒绝，模型闪烁。retime 把时间戳换成 PC 本地时钟——**这是分布式机器人系统的经典工程问题**。

### A2. 板端只读桥：怎么读机械臂关节

**核心代码**（`so101_joint_source.py` 的精髓）：

```python
# 用 USB 序列号找从臂，不依赖 /dev/ttyACM0 这种会变的编号
follower_port = serial_port(FOLLOWER_SERIAL, "follower")  # 5C82108953

# 构建电机总线：6 个 STS3215 舵机
bus = FeetechMotorsBus(
    port=follower_port,
    motors={
        "shoulder_pan": Motor(1, "sts3215", MotorNormMode.DEGREES),
        ...
    },
    calibration=load_calibration(CALIBRATION_PATH),
)
bus.connect()
positions = bus.sync_read("Present_Position", normalize=True)  # 同步读全部关节
```

**为什么这么做**：

| 设计 | 原因 | 学习点 |
|---|---|---|
| USB 序列号找设备 | 机械臂热插拔后 /dev/ttyACM* 编号会变，序列号恒定 | 硬件识别要稳定标识而非动态编号 |
| `sync_read` 一次读全部 | 分次读会引入关节间的时间差（不是同一时刻的姿态） | 多传感器同步采样 |
| 校准文件 | 舵机原始编码器值 → 真实角度需要偏移和缩放（homing_offset） | 传感器校准概念 |
| 只读不写 | 这个程序只采集，绝不发控制指令，保证安全 | 职责分离、安全边界 |

**能学到**：电机总线通信（Feetech STS3215 是串口总线舵机）、校准的必要性（原始编码器 0~4095 不代表角度 0°）、同步采样。

### A3. 轨迹记录节点：怎么算末端位置

**核心逻辑**（`ee_trajectory_recorder.py`）：

```python
# 1. 订阅关节状态，触发采样
def joint_state_cb(self, msg):
    # 2. 通过 TF 查询末端(gripper_frame_link)在底座坐标系的位置
    transform = self.tf_buffer.lookup_transform("base_link", "gripper_frame_link", Time(), ...)
    # 3. 记录 (时间, x, y, z)
    self.samples.append((now, t.x, t.y, t.z))
```

**为什么用 TF 而不是自己算**：TF 是 ROS2 的「坐标变换服务器」，robot_state_publisher 已经把关节角转成了所有连杆的坐标。recorder 只要查一下「末端在 base 系的位置」就行——**不用重复实现正运动学**。这是 ROS2 的核心理念：**每个节点只做一件事，坐标变换交给 TF**。

**统计计算**（学习数学应用）：

```text
轨迹长度 = Σ 相邻采样点距离          ← 弧长积分
速度     = 位移 / 时间差             ← 差分求导
加速度   = 速度变化 / 时间差         ← 二阶差分
曲率     = |v × a| / |v|³            ← 描述路径弯曲程度（平滑度）
重复误差 = 多圈轨迹同名次点距离 RMS  ← 一致性度量
```

**能学到**：TF 查询、弧长积分、数值微分、曲率计算——这些都是机器人运动分析的常用数学。

### A4. 圆检测：一个有意思的算法问题

**需求**：用户画圆时，自动检测「画完了一圈」。

**启发式算法**（不用机器学习，纯几何）：

```python
# 当末端回到起点附近（<2cm）且已走过足够距离（>15cm），判定一圈闭合
if arc_length > circle_min_arc and dist_to_start < circle_close_tol:
    self.circles.append(closed_points)  # 这一圈存下来
    circle_start_index = len(self.samples) - 1  # 新圈起点
```

**为什么这么设计**：画圆不是完美的——手会抖、起点会漂移。所以不能要求「精确回到起点」，而是「回到起点附近 + 走过足够弧长」两个条件同时满足才判定闭合。

**能学到**：真实世界信号的容错处理——启发式判定的阈值设计（太大误判、太小漏判），以及为什么需要「弧长下限」防止小抖动被误判成圈。

### A5. 数字孪生：叠加真实世界信息

**目标**：在 RViz 机械臂模型上，叠加真实的工作空间边界、禁区、关节角度文字。

**实现**（`digital_twin_layers.py`）：

**实际工作区配置**（从真实测量得到）：

2. **Marker 消息**：RViz 的可视化消息类型丰富（CUBE/SPHERE/LINE_STRIP/TEXT），是「调试可视化」的核心工具；
3. **JSON 字符串参数**：Humble 的 rcl 参数解析器不支持「数组元素为 map」，所以复杂配置用 JSON 字符串传入，节点内解析——**ROS2 参数系统的限制与绕过**。

## 项目 B：物块定位（相机标定与坐标变换）

### B0. 为什么要做这个项目

**问题**：相机能看到物体（黄色物块），但相机看到的只是「图像上的像素点」。机械臂需要的是「物体在底座坐标系下的 3D 位置」。像素 → 3D 的转换就是**相机标定**要解决的。

**学习目标**：掌握相机成像模型（内参）、相机与机器人坐标的关系（外参）、像素反投影（ray casting）、以及手眼标定（eye-in-hand / eye-to-hand）——这是所有视觉机器人（抓取、导航、避障）的公共基础。

### B1. 相机成像模型：像素到底代表什么

**核心概念**：相机把 3D 世界的点映射到 2D 图像，用**内参矩阵**描述：

```text
[u]   [fx  0  cx] [X/Z]
[v] = [ 0 fy  cy] [Y/Z]
[1]   [0   0   1] [ 1 ]

fx, fy = 焦距（像素单位，= 物理焦距 × 像素密度）
cx, cy = 光心（图像中心像素坐标）
X, Y, Z = 物体在相机坐标系下的 3D 坐标
u, v   = 物体在图像上的像素坐标
```

**内参为什么要标定**：每个相机的 fx/fy/cx/cy 都不同（制造公差），还带畸变（镜头边缘弯曲）。标定就是**用已知几何的图案（棋盘格）反推这些参数**。

**能学到**：小孔成像模型、内参矩阵、畸变（径向/切向）——这是计算机视觉的第一课。

### B2. 内参标定：用棋盘格反推相机参数

**原理**：棋盘格的角点位置是**已知的**（比如 11×8 内角点，格距 10mm）。拍一张棋盘格照片，检测角点像素位置，OpenCV 就能解出「什么内参能把已知 3D 点投影到这些像素」。

**做法**（`front_intrinsics_v2.json`）：

```python
# 1. 检测棋盘格角点（亚像素精度）
found, corners = cv2.findChessboardCorners(gray, (cols, rows), flags)
corners = cv2.cornerSubPix(gray, corners, (11, 11), (-1, -1), criteria)

# 2. 构建已知 3D 点（棋盘格平面上，z=0）
objp = np.zeros((cols * rows, 3), np.float32)
objp[:, :2] = np.mgrid[0:cols, 0:rows].T.reshape(-1, 2) * square_size

# 3. 多张照片联合求解内参
ret, mtx, dist, _, _ = cv2.calibrateCamera(obj_points, img_points, (w, h), None, None)
```

**关键经验（今天踩的坑）**：

| 错误做法 | 结果 | 正确做法 |
|---|---|---|
| 棋盘格在画面里太小（相机太高） | 内参误差 6.4px（差） | 手拿棋盘格贴近相机，占画面 2/3 → 0.74px |
| 只有正对平面的照片 | 畸变估计不准 | 多种倾斜角度（30°~60°） |
| 重投影误差 >1px | 定位误差放大 | 目标是 <1px |

**能学到**：**标定数据质量比算法更重要**——棋盘格大小、角度多样性、照片数量直接决定精度。误差 0.74px vs 6.4px 差了 8 倍，全是因为拍摄方式。

### B3. 外参标定：相机和机械臂的位置关系

### B4. 前置相机（eye-to-hand）标定的正确方法

**踩坑记录（这是今天最大的坑）**：

**❌ 错误路线**：用 `cv2.calibrateHandEye` 解 eye-to-hand。
**为什么错**：OpenCV 的 `calibrateHandEye` **只有 eye-in-hand 模式**（输出恒为 camera→gripper），强行用于 eye-to-hand 得到的结果不可靠。折腾了 v1/v2/v3 三个版本全不对。

**✅ 正确路线：几何法（single-shot）**。

原理：棋盘格平放桌面**已知位置**，相机固定。已知：
- 棋盘格角点的 3D 位置（在 base_link 系，量出来的）；
- 棋盘格角点的像素位置（图像检测）。

`solvePnP` 一次就解出「相机在棋盘格坐标系」的位姿，组合棋盘格→base 变换即得 相机→base：

```python
# 棋盘格中心在 base_link 的位置（实测：前方 29.3cm、居中、高 0.3cm）
CENTER = (0.293, 0.0, 0.003)

# 构建 88 个角点在 base_link 的 3D 坐标（长边朝 Y）
objp = build_board_points(11, 8, 0.010, CENTER)  # 角点网格，中心对齐

# solvePnP：求「棋盘格在相机系」的位姿 (R, t)
ok, rvec, tvec = cv2.solvePnP(objp, corners, mtx, dist)
R = cv2.Rodrigues(rvec)[0]

# 关键：rvec/tvec 是「相机在棋盘系」还是「棋盘在相机系」？
# OpenCV 约定：是 棋盘→相机。组合成 相机→base：
#   T_cam2base = [R.T | -R.T·t]   ← 用 R 的转置！不要多加 T_b2base 平移
T_cam2base = np.eye(4)
T_cam2base[:3, :3] = R.T
T_cam2base[:3, 3] = -R.T @ t
```

**为什么 `T_cam2base = [R.T | -R.T·t]`**：solvePnP 返回的 (R, t) 满足 `p_cam = R · p_board + t`（把棋盘系点转到相机系）。要求「相机在 base 系」，就是它的逆变换：`R_inv = R.T`，`t_inv = -R.T · t`。

**为什么不能多加 T_b2base**：因为角点 3D 坐标**已经直接建在 base 系**了（build_board_points 输出就是 base 坐标），棋盘系 ≡ base 系，不需要再乘棋盘→base 的变换。多加一步就把位置搞错了 16cm（今天实测踩的坑）。

**自检方法（今天学到的金标准）**：标定完必须自检——把棋盘格中心像素反投影回 base，应该得到 (29.3, 0, 0.3)cm：

```text
标定前：反投影 (12.7, -5.3)cm ❌（多加了 T_b2base）
修正后：反投影 (29.3, 0.0, 0.3)cm ✅ 分毫不差
```

**能学到**：
1. **标定的自检闭环**：用已知点反投影验证，比看重投影误差更直观；
2. **坐标系约定的痛苦**：R 转置、T 组合、Z 轴方向（俯视相机光轴必须朝下）——每一个都是「错一个符号就全错」的陷阱；
3. **为什么单点不够**：几何法用一张照片，但棋盘格位置测量误差会直接进外参。今天用物块真值（实测位置）反推棋盘格真实中心 (23.5, 7.0)cm（之前量的 29.3 偏了），才最终校准到位。

**最终精度验证**（双点测试）：

| 物块实际位置 | 定位结果 | 误差 |
|---|---|---|
| (23, 13) cm | (23.0, 12.9) cm | ~0 |
| (18, -13) cm | (17.5, -14.3) cm | ~1.3cm |

### B5. 手眼相机（eye-in-hand）标定

手眼相机在腕部，随机械臂动。标定目标是「相机→末端」的固定变换。

**方法**：`cv2.calibrateHandEye`（这次是对的，因为就是 eye-in-hand）：

```python
# 输入：
#   R_gripper2base, t_gripper2base  ← 每个姿态下末端在底座系（FK 计算）
#   R_target2cam, t_target2cam      ← 每个姿态下棋盘格在相机系（solvePnP）
# 输出：camera → gripper 的固定变换
R_cam2grip, t_cam2grip = cv2.calibrateHandEye(
    R_gripper2base, t_gripper2base, R_target2cam, t_target2cam,
    method=cv2.CALIB_HAND_EYE_TSAI)
```

**原理（AX=XB）**：机械臂动 15 个姿态，每个姿态下：
- A = 末端运动的变换（末端→底座）；
- B = 棋盘格在相机里的运动变换；
- X = 相机→末端（恒定，因为相机固定在末端上）。

它们满足 **A·X = X·B**，解这个矩阵方程就是手眼标定。Tsai 是经典求解方法。

**今天的结果**：内参 0.46px（优秀），外参平移 (-3.5, 63.7, -91.1)mm。

**⚠️ 遗留疑点**：实测手眼相机在夹爪**左侧 5cm**，但外参 y=+63.7mm——方向可能标反（和前置相机一样的 y 镜像问题）。这导致抓取时 y 方向偏差，用 `--handeye-offset-y +0.05` 手动补偿。**这是下一步要重标的地方**。

**能学到**：
1. **AX=XB 的数学**：手眼标定的本质是解矩阵方程，多姿态采集是为了方程有解；
2. **eye-in-hand vs eye-to-hand 的区别**：一个输出 camera→gripper，一个要 camera→base，**OpenCV 只支持前者**，后者要用几何法或 AX=ZB 专用求解器；
3. **标定结果的物理验证**：外参方向是否合理（相机装哪边、光轴朝哪）必须用物理事实核对，不能只看数字。

### B6. 像素 → 3D：反投影（ray casting）

有了内参 + 外参，就能把物块像素反投影成 base_link 的 3D 坐标：

```python
def pixel_to_3d(u, v, mtx, dist, T_cam2base, table_z=0.0):
    # 1. 去畸变：像素 (u,v) → 理想像素
    und = cv2.undistortPoints(points, mtx, dist, P=mtx)
    # 2. 相机系射线方向（z=1 归一化）
    d_cam = np.array([(uu - cx) / fx, (vv - cy) / fy, 1.0])
    d_cam /= np.linalg.norm(d_cam)
    # 3. 转到 base 系
    d_base = T_cam2base[:3, :3] @ d_cam
    origin = T_cam2base[:3, 3]  # 相机在 base 系的位置
    # 4. 射线与桌面平面 (z=table_z) 求交
    t = (table_z - origin[2]) / d_base[2]
    P = origin + t * d_base
    return P
```

**为什么需要「假设在桌面上」**：单目相机一个像素只能确定一条射线（方向），无法确定距离。但抓取场景里物体放在桌面上（z=0 已知），射线与平面求交就得到了 3D 点——**先验知识（物体在桌面上）补足了缺失的深度信息**。这是单目 3D 定位的经典技巧。

**能学到**：去畸变、相机系→base 系的变换、射线-平面求交——把「图像坐标」变成「机器人坐标」的完整链路。

## 项目 C：抓取闭环（IK、执行控制与视觉伺服）

### C0. 为什么要做这个项目

**问题**：定位到物块位置后，怎么让机械臂**动到那里并夹住它**？这需要：
1. **逆运动学（IK）**：把「末端要到的位置」换算成「六个关节要转的角度」；
2. **执行控制**：把关节角度发给舵机，安全地动过去；
3. **视觉伺服**：粗定位不准时，用相机反馈逐步逼近。

**学习目标**：IK 求解、关节空间插值、两级定位（粗+精）、以及「为什么视觉抓取这么难调」。

### C1. 逆运动学（IK）：位置 → 关节角

**正运动学（FK）**：已知关节角 → 求末端位置（简单，链式矩阵相乘）。
**逆运动学（IK）**：已知末端位置 → 求关节角（难，可能无解/多解/无穷解）。

**SO-ARM101 的 IK 难点**：5 个定位关节 + 1 个夹爪，但末端位置只有 3 个自由度（x,y,z）——**欠约束**（5 个变量解 3 个方程），有 2 个自由度冗余。

**今天的方案：数值 IK（阻尼最小二乘）**：

```python
def solve_ik(joints, target_xyz, initial=None, max_iter=300, tol=1e-5, damping=1e-4):
    # 迭代：每步算雅可比（末端位置对每个关节的偏导数），求关节增量
    for it in range(max_iter):
        T = forward_kinematics(joints, q, TIP)      # 当前末端位置
        err = target_xyz - T[:3, 3]                 # 位置误差
        if np.linalg.norm(err) < tol:
            break
        # 数值雅可比：每个关节 ±h 扰动，看末端移动多少
        J[:, i] = (FK(q+h) - FK(q-h)) / (2*h)
        # 阻尼最小二乘：dq = Jᵀ (J·Jᵀ + λI)⁻¹ e
        dq = J.T @ np.linalg.solve(J @ J.T + damping * np.eye(3), err)
        # 线搜索：逐步减小步长避免过冲，并夹到关节限位内
        q = line_search(q, dq, target)
    return q
```

**为什么用「阻尼最小二乘」而不是直接求逆**：欠约束系统 J 不是方阵，J⁻¹ 不存在。`J·Jᵀ + λI` 加了个小阻尼 λ，保证矩阵可逆且步长可控——**这是处理冗余/奇异机器人 IK 的标准技巧**。

**今天的重大教训：初始猜测决定成败**：

```text
❌ 初始 = 全零位姿 → IK 陷入局部最优，误差 18cm
✅ 初始 = 自然前伸姿态（shoulder_lift 60°, elbow -90°）→ 误差 0.0cm
```

**为什么**：数值 IK 是迭代优化，会收敛到「离初始猜测最近的局部最优」。全零位姿离目标太远，优化掉进错误的山谷。**给一个接近真实解的初始猜测**（比如当前关节角或一个自然姿态）是数值 IK 的关键工程技巧。

**能学到**：
1. FK vs IK 的本质区别；
2. 数值雅可比、阻尼最小二乘、线搜索——数值优化的经典方法；
3. **初始猜测的重要性**（数值方法通用经验）；
4. 冗余自由度（5 关节解 3 约束）的数学处理。

### C2. 夹爪朝向：让夹爪垂直朝下

**需求**：抓取时夹爪要**垂直朝下**（物块在桌面上，从上方夹）。

**做法**（`add_downward_wrist`）：位置 IK 解完后，单独调 wrist_flex 让末端 Z 轴对准 [0,0,-1]：

```python
# 扫描 wrist_flex 所有可能角度，选让夹爪 Z 轴最接近朝下的
for wf in np.linspace(-109°, 109°, 2000):
    q["wrist_flex"] = wf
    z = FK(q)[:3, 2]          # 夹爪 Z 轴方向
    align = z · [0,0,-1]      # 与朝下的对齐程度
    # 保留 align 最大的
```

**为什么单独调**：位置 IK 不管朝向（5 个关节解位置已经很灵活），wrist_flex 单独扫描保证朝向——**把「位置」和「姿态」解耦处理**，简化问题。

### C3. 执行控制：从角度到舵机

**LeRobot 的 `SO101Follower`** 封装了串口控制：

```python
robot = SO101Follower(SO101FollowerConfig(port=port, id="my_awesome_follower_arm"))
robot.connect()
robot.send_action({"shoulder_pan.pos": 13.4, ..., "gripper.pos": 50.0})
robot.get_observation()  # 读实际关节角（不是 read_observation！）
```

**今天的坑：`max_relative_target` 限幅导致动不到位**：

```text
第一次：目标 should_lift 9.4°，实际机械臂在 -72.5°（差 82°）
        send_action 一次只允许动 10° → 被夹到 -94.6°，根本没到目标
        （而且下一步就 sleep 2s，机械臂一路都没到位）
```

**解决：插值多步执行**：

```python
def move_to(target):
    current = read_actual()               # 读当前实际角度
    steps = ceil(max_delta / max_step)    # 需要几步（每步 ≤30°）
    for s in range(1, steps+1):
        interp = current + (target-current) * (s/steps)  # 线性插值
        robot.send_action(action_dict(interp))
        time.sleep(settle/steps)          # 每步等舵机跟上
    robot.send_action(action_dict(target)) # 最终精确目标
```

**为什么限幅很重要**：舵机有速度极限，一步给 82° 的目标会让舵机猛冲（危险）。限幅 = 每步最多动 30°，分 3 步温和到位——**安全控制的第一原则**。

**能学到**：
1. 关节限幅、插值执行——机器人安全控制基础；
2. `get_observation` vs `read_observation`——**API 名字差一点就崩**（今天踩的）；
3. 为什么「读实际位置」比「记目标位置」可靠（舵机可能没跟上）。

### C4. 两级定位：粗定位 + 精定位

**为什么需要两级**：
- 前置相机（俯视固定）：定位误差 ±1.5cm——够「走到附近」，不够「精确抓取」；
- 手眼相机（腕部）：离物块近、精度高——但视野小，只能看到近处。

**工业标准方案**：前置粗定位（走向物块上方 20cm）→ 手眼精定位（看准精确位置）→ 下降抓取。

### C5. 夹爪几何：为什么下爪戳到物块中心

**问题**：夹爪下爪落在物块中心而不是边缘，夹不住。

**根因**：IK 控制的参考点 `gripper_frame_link` 在**夹爪下方 ~9.8cm**（URDF 里 `gripper_frame_joint` 的 origin z=-0.098）——它是标定参考点，不是夹爪咬合点。IK 让参考点对准物块中心，夹爪实际在参考点上方，看起来「下爪戳中心」。

**解决**：抓取目标 x 用「物块下边缘 - 余量」：

```python
# 检测物块包围盒，得到 x_min（下边缘）
bbox = detect_block_bbox(...)   # x_min, x_max, y_min, y_max, center
# 下爪（x 负侧）落在物块下边缘外侧 1.5cm
gx = x_min - jaw_clearance      # 物块能从 x 正侧滑入爪缝
gy = center_y                   # y 用质心（比 bbox 中心稳）
```

**能学到**：
1. **参考系 vs 物理抓取点**：URDF 里的坐标系不一定是机械结构的关键点，抓取要算清「夹爪咬合点」相对参考点的偏移；
2. **边缘对齐策略**：夹爪张开时，目标点应该让物块「滑进爪缝」而不是「戳中心」；
3. **质心 vs 包围盒中心**：物块倾斜时，轮廓质心比 bbox 中心更接近真实中心。
