# 从零开始：SO-ARM101 轨迹可视化（项目 2）实操教程

> 日期：2026-08-16
> 适用范围：Atlas 200I DK A2 开发板 + SO-ARM101 双臂 + Windows PC（WSL2）
> 目标：在 RViz 中实时显示从臂末端轨迹，画圆时自动统计圈数、半径、重复误差

---

## 0. 你需要准备的东西

| 物品 | 说明 |
|---|---|
| Atlas 200I DK A2 开发板 | Ubuntu 22.04，已装 LeRobot + ROS2 Humble |
| SO-ARM101 双臂 | 主臂（Leader）+ 从臂（Follower），USB 已接 |
| 双 USB 相机 | 手眼（PID 9005）+ 前置（PID 9221） |
| Windows PC | 已配 WSL2 Ubuntu 22.04 + ROS2 Humble + VcXsrv |
| Type-C 数据线 | 连接 PC 与开发板（网络 192.168.0.2） |
| **MobaXterm** | 控制开发板的图形化 SSH 客户端（已配置 `Ascend-devkit` 会话） |

**首次操作前检查硬件：**

```powershell
# PC 上检查开发板网络
ping 192.168.0.2
Test-NetConnection 192.168.0.2 -Port 22    # SSH
Test-NetConnection 192.168.0.2 -Port 7447  # Zenoh
```

## 1. 开发板启动 + 只读桥

### 1.1 用 MobaXterm 打开开发板会话

1. 打开 **MobaXterm**（Personal Edition v22.1）；
2. 左侧 **Sessions** 列表双击 **`Ascend-devkit`**（SSH 到 `root@192.168.0.2`）；
3. 连接成功后终端提示符为：`(base) root@davinci-mini:~#`；
4. 左侧 **SSH-browser** 文件树可直接浏览板端 `/root/lerobot_project` 等目录。

> 💡 提示：
> - 终端前缀 `(base)` 是板端 conda 环境自动激活，本教程命令都用绝对路径（如 `/opt/lerobot061/bin/python`）或 `systemctl`，不受 conda 影响；
> - 需要多开终端时：右键顶部标签页 → **Duplicate**，或点右上角 **+** 新建；
> - MobaXterm 自带 X server 且 X11 转发已开启（会话属性可见），本教程板端不需要图形界面，仅用终端。

### 1.2 检查硬件识别

```bash
ls -l /dev/ttyACM* /dev/video*
# 预期：/dev/ttyACM0（主臂） /dev/ttyACM1（从臂） /dev/video0..3
```

### 1.3 启动只读关节状态桥

```bash
systemctl start so101-rviz-bridge.service
systemctl is-active so101-rviz-bridge.service
# 预期输出：active
```

> ⚠️ 只读桥会占用从臂串口。如果后续要跑遥操作或模型推理，必须先 `systemctl stop so101-rviz-bridge.service`。

### 1.4 （可选）板端自检数据

```bash
source /root/ros2_humble_env.sh
timeout 6 ros2 topic echo /joint_states --once
# 预期：能看到 shoulder_pan / shoulder_lift / ... 六个关节的位置值
```

## 4. 启动轨迹可视化

### 4.1 方式 A：一键启动（推荐，VcXsrv 显示）

在 **Windows PowerShell** 中（WSLg 故障时用 VcXsrv）：

```powershell
powershell -ExecutionPolicy Bypass -File F:\robot_arm_atlas\ros2\start_so101_trajectory_vcxsrv.ps1
```

预期：
1. 弹出 VcXsrv 窗口（:1 显示）；
2. WSL 里自动启动 retime + robot_state_publisher + recorder + RViz2；
3. RViz 窗口出现机械臂模型（灰色网格 + 彩色模型）。

### 4.2 方式 B：手动启动（WSLg 正常时）

```bash
source ~/ros2_humble_env.sh
ros2 launch so101_visualization trajectory_viz.launch.py
```

### 4.3 方式 C：只起数据链路、不开 RViz（无图形环境/服务器）

```bash
source ~/ros2_humble_env.sh
ros2 launch so101_visualization trajectory_viz.launch.py with_rviz:=false
```

## 5. 开始画圆（主臂带动从臂）

### 5.1 先停只读桥（释放串口），再启动遥操作

在 **MobaXterm** 的开发板会话中（建议 Duplicate 开一个新标签页，保留当前终端）：

```bash
systemctl stop so101-rviz-bridge.service
cd /root/lerobot_project
/opt/lerobot061/bin/python 03_teleoperate_with_rviz.py
```

> ⚠️ 安全要求：
> - 两臂姿态先接近（防止启动跳变）；
> - 工作区清空，人在旁边随时按 Ctrl+C；
> - 首次运行可加 `--dry-run` 检查识别：
>   `/opt/lerobot061/bin/python 03_teleoperate_with_rviz.py --dry-run`
> - 遥操作程序自己发布 `/joint_states`（会顶替只读桥），所以 4.1 的 launch 不用重启。

### 5.2 画圆操作

1. 双手握住**主臂**末端，缓慢画 3-5 个圆；
2. 从臂跟随主臂运动；
3. 观察 RViz：白色细线是当前轨迹，每画完一圈会变成一种颜色（圈1红、圈2橙……12 色轮换）；
4. 末端绿色小球表示当前夹爪位置，上方白色文字实时显示 `L=长度 v=速度 circles=圈数`。

### 5.3 查看统计

在 WSL 开一个终端：

```bash
source ~/ros2_humble_env.sh
ros2 topic echo /ee_stats --once
```

预期输出示例：

```json
{"points": 419, "circles_closed": 3,
 "circle_radius_m": [0.12, 0.118, 0.121],
 "circle_error_rms_m": [0.0, 0.008, 0.011],
 "arc_length_m": 2.3, "speed_mean_mps": 0.15,
 "speed_max_mps": 0.42, "accel_mean_mps2": 0.08,
 "curvature_mean": 8.2, "curvature_max": 45.0,
 "duration_s": 21.0}
```

字段含义：

| 字段 | 含义 |
|---|---|
| `points` | 采样点数（50Hz 上限） |
| `circles_closed` | 已闭合的圈数 |
| `circle_radius_m` | 每圈平均半径（米） |
| `circle_error_rms_m` | 每圈与第一圈的重复误差 RMS（米） |
| `arc_length_m` | 总轨迹长度（米） |
| `speed_mean/max` | 平均/最大速度（m/s） |
| `accel_mean/max` | 平均/最大加速度（m/s²） |
| `curvature_mean/max` | 曲率（平滑度指标，越小越平滑） |

### 5.4 清空轨迹重新画

```bash
ros2 service call /ee_trail/reset std_srvs/srv/Empty
```

## 6. 画圆场景二：MoveIt 规划自动画圆

前提：MoveIt 真实控制链路已通（见 `moveit_real_arm_control/技术文档.md`）。

MoveIt 的 `real_arm.launch.py` **自带** retime + robot_state_publisher + RViz，所以轨迹 recorder 要复用它的数据链路，用 `with_retime:=false with_rsp:=false` 只启动 recorder + 轨迹 RViz（避免节点重名冲突）：

```bash
# WSL 终端 1：MoveIt 真实控制（含 move_group + 普通 RViz）
source ~/ros2_humble_env.sh
ros2 launch so101_moveit_config real_arm.launch.py

# WSL 终端 2：只启动轨迹 recorder + 轨迹 RViz（复用终端 1 的 retime/rsp）
source ~/ros2_humble_env.sh
ros2 launch so101_visualization trajectory_viz.launch.py with_retime:=false with_rsp:=false
```

在终端 1 的 RViz MotionPlanning 面板规划/执行圆形轨迹，终端 2 的轨迹 RViz 自动记录执行过程（recorder 同样订阅 `/joint_states_local`）。

## 7. 导出 CSV 轨迹（可选）

直接用 launch 的 `out_file` 参数，数据链路（retime/rsp/recorder）由 launch 一起管理：

```bash
# WSL：正常启动 + 指定 CSV 输出（替换原命令）
source ~/ros2_humble_env.sh
ros2 launch so101_visualization trajectory_viz.launch.py out_file:=~/trajectory_20260816.csv
```

> 也可以直接 `ros2 run so101_visualization ee_trajectory_recorder.py --out-file ~/trajectory.csv`，但那样需要单独另开 retime + robot_state_publisher，容易漏，推荐用 launch 方式。

CSV 列：`t_s, x_m, y_m, z_m, vx, vy, vz, speed, accel, curvature`

### 8.1 停止画圆

- 在 **MobaXterm** 遥操作终端按 `Ctrl+C`（开发板）；
- 程序会自动断开双臂并关闭从臂扭矩。

### 8.2 停止可视化

- 方式 A：在 PowerShell 窗口按 `Ctrl+C`（会停 RViz + recorder + rsp + retime）；
- 方式 C：`kill` 对应进程，或直接关终端。

### 8.3 恢复只读模式（可选）

```bash
# MobaXterm 开发板会话

```

## 9. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `colcon build` 报 install 布局错误 | 少了 `--merge-install`（本工作区 install 是 merged 布局） | 用第 3 步完整命令：`colcon build --packages-select so101_visualization --merge-install --symlink-install` |
| RViz 没有机械臂模型 | 没起 robot_state_publisher 或 /joint_states 无数据 | 检查第 2 步 WSL 能否收到 /joint_states |
| 轨迹没画出来 | recorder 没起 / TF 没数据 | `ros2 topic list` 看有没有 `/ee_path`、`/ee_trail` |
| `/ee_stats` 显示 `points: 0` | 关节状态没到达 recorder | 确认 `ros2 topic hz /joint_states` 有频率 |
| 画圆不闭合（一直白线） | 回到起点距离 > 2cm，或弧长 < 15cm | 把圆画大些、画完整；或调参数 |
| 圈数统计比实际多/少 | `--circle-close-tol` 阈值不合适 | 按需调整：`--circle-close-tol 0.03 --circle-min-arc 0.2` |
| 串口被占用 | 只读桥和遥操作同时跑 | 先 `systemctl stop so101-rviz-bridge.service` |
| RViz 窗口黑屏 | WSLg GPU-PV 故障 | 用方式 A（VcXsrv），或重启 Windows 后恢复 WSLg |

### 调参示例（recorder 参数）

```bash
# 更宽松的圆闭合（允许起点漂移 3cm，最小弧长 20cm）
ros2 run so101_visualization ee_trajectory_recorder.py \
  --circle-close-tol 0.03 --circle-min-arc 0.2
```

## 10. 无硬件自检（可选，验证软件链路）

不需要机械臂也能验证（用 mock 关节源模拟画圆）。**三个终端都要先 source 环境**，且 mock 测试用独立域 66 避免和开发板域 42 串扰：

```bash
# 终端 1：mock 关节源（模拟画 3 圈）
source /opt/ros/humble/setup.bash && source ~/ros2_ws/install/setup.bash 2>/dev/null || true
export ROS_DOMAIN_ID=66 ROS_LOCALHOST_ONLY=1
ros2 run so101_visualization mock_joint_source.py --rate 30 --circles 3 --period 4.0

# 终端 2：可视化链路（不开 RViz，适合无图形环境；有图形可去掉 with_rviz:=false）
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=66 ROS_LOCALHOST_ONLY=1
ros2 launch so101_visualization trajectory_viz.launch.py with_rviz:=false

# 终端 3：查看统计（等终端 1 画完约 12 秒后执行）
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=66 ROS_LOCALHOST_ONLY=1
ros2 topic echo /ee_stats --once
# 预期：circles_closed >= 2（mock 画 3 圈，最后 1 圈可能未闭合）
```

> ⚠️ 注意：mock 自检**不要** source `~/ros2_humble_env.sh`（它会把 RMW 切到 Zenoh 并连开发板），只用 `/opt/ros/humble/setup.bash` + 域 66 本地模式即可。
