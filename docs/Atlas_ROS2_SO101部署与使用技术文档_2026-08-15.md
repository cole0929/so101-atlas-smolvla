## 2. PC 端和开发板分别负责什么

### 2.1 Atlas 开发板

开发板是连接真实硬件的一端，负责：

1. 连接主臂和从臂串口。
2. 通过 LeRobot 读取真实关节位置。
3. 在遥操作模式下，把主臂动作发送给从臂。
4. 把从臂实时状态转换为 ROS 2 `sensor_msgs/JointState`。
5. 发布 `/joint_states`。
6. 运行 Zenoh 路由器，把 ROS 2 数据送到 WSL。

开发板不安装 RViz2 和 Gazebo。它只安装 `ros-base`，这样更省磁盘、内存和图形资源。

### 2.2 Windows PC / WSL2

PC 是显示和开发的一端，负责：

1. 运行 RViz2 图形界面。
2. 加载 SO-ARM101 的 URDF 和 STL 模型。
3. 将 `/joint_states` 转换为 TF 坐标树。
4. 在 RViz2 中实时显示从臂姿态。
5. 保存 ROS 工作空间、模型和源代码。
6. 提供 Gazebo 11；当前尚未创建 SO-ARM101 的 Gazebo 仿真世界和控制器配置。

PC 端 RViz2 本身不会控制电机。它显示的是开发板发布的实际从臂状态。

## 3. 数据流架构

```text
SO-ARM101 主臂 ──串口──┐
                       ├─ Atlas 开发板 / LeRobot 遥操作程序 ──命令──> SO-ARM101 从臂
SO-ARM101 从臂 ──串口──┘                  │
                                         │ 从臂观测（本机 UDP 15000）
                                         v
                               so101_joint_bridge.py
                                         │ /joint_states
                                         v
                   Atlas Zenoh Router（192.168.0.2:7447）
                                         │
                                         v
                       Windows WSL2 / rmw_zenoh_cpp 客户端
                                         │
                         joint_state_retime.py（重打时间戳）
                                         │ /joint_states_local
                                         v
                            robot_state_publisher ──> /tf
                                         │
                                         v
                                      RViz2
```

`joint_state_retime.py` 在 PC 端重新生成时间戳，避免开发板和 Windows 时钟偏差导致模型闪烁或时隐时现。

## 12. ROS 环境和 Python 环境注意事项

### 开发板 ROS 终端

```bash
source /root/ros2_humble_env.sh
```

ROS Humble 的 `rclpy` 使用系统 Python 3.10。不要用 Conda Python 3.9 或其他虚拟环境的 Python 导入它。

正确：


LeRobot 则继续使用自己的环境：

```bash

```

因此当前架构将 LeRobot 和 ROS Python 分为两个进程，通过开发板本机 UDP 通信，避免 Python 和动态库版本冲突。

### WSL ROS 终端


## 14. 常见故障排查

### 14.1 `No module named rclpy._rclpy_pybind11`

原因：ROS 桥接器被 Conda Python 3.9 启动，而 ROS Humble 的扩展是为 Python 3.10 编译的。

当前脚本已经修复为固定使用 `/usr/bin/python3`。正常情况下，即使终端前面显示 `(base)` 也不再受影响。

检查修复是否仍在：

```bash
grep -n /usr/bin/python3 /root/lerobot_project/03_teleoperate_with_rviz.py
grep -n /usr/bin/python3 /root/lerobot_project/start_so101_rviz_bridge.sh
```

### 14.2 RViz2 没有机械臂动作

依次检查：

```bash
# 开发板
systemctl status zenoh-router.service --no-pager
systemctl status so101-rviz-bridge.service --no-pager
source /root/ros2_humble_env.sh
ros2 topic hz /joint_states
```

```bash
# WSL
source ~/ros2_humble_env.sh
ros2 topic hz /joint_states
ros2 topic hz /joint_states_local
```

如果是遥操作模式，`so101-rviz-bridge.service` 显示 `inactive` 是正常的，因为 `03_teleoperate_with_rviz.py` 自己发布状态。

### 14.3 串口被占用

只读服务和遥操作程序不能同时读取同一个从臂串口。

手动运行其他 LeRobot 或 SmolVLA 程序前执行：

```bash
systemctl stop so101-rviz-bridge.service
```

查看相关进程：

```bash
pgrep -af 'so101|teleoperate|lerobot'
```

查看稳定的 USB 设备标识：

```bash
ls -l /dev/serial/by-id/
```

当前脚本通过 USB 序列号识别设备，而不是依赖可能变化的 `/dev/ttyACM0`、`/dev/ttyACM1` 编号：

- 从臂：`5C82108953`
- 主臂：`5C4C123788`

### 14.4 RViz2 字体太小

默认已经设置两倍缩放。如果需要临时调整：

```bash
source ~/ros2_humble_env.sh
QT_SCALE_FACTOR=2.5 ros2 launch so101_description display.launch.py
```

若 2.5 倍显示异常，可使用整数倍：

```bash
QT_SCALE_FACTOR=3 ros2 launch so101_description display.launch.py
```

### 14.5 RViz2 频闪或帧率较低

当前环境默认使用稳定的软件 OpenGL：

```bash
echo "$LIBGL_ALWAYS_SOFTWARE"
```

预期为 `1`。SO-ARM101 场景较轻，软件渲染更稳定，但帧率可能低于独立显卡渲染。

还要确保只启动一个 RViz launch。检查是否出现重复节点：

```bash
source ~/ros2_humble_env.sh
ros2 node list
```

如果同名节点出现警告，应回到旧终端按 `Ctrl+C`，只保留一个 `display.launch.py`。

### 14.6 只有网格，没有数据或出现 Fixed Frame 警告

确认以下话题存在并有数据：

```bash
ros2 topic list
ros2 topic echo /joint_states_local --once
ros2 topic echo /tf --once
```

RViz2 的 Fixed Frame 应使用 URDF 根坐标系；当前提供的 RViz 配置会自动加载正确设置。

## 14.7 WSLg 黑屏故障与 VcXsrv 绕过（2026-08-15 晚）

### 现象

在 WSL 里运行以下命令时，RViz 窗口在任务栏出现图标但内容全黑，点击无法操作：

```bash
source ~/ros2_humble_env.sh
ros2 launch so101_description display.launch.py
```

### 根因

- 当天 12:51 安装了 WSL 2.7.11.0（MSI，安装包位于 `F:\robot_arm_atlas\.tmp\wsl.2.7.11.0.x64.msi`）。
- 16:45 WSL 重启后，GPU 直通（dxgkrnl）初始化失败，dmesg 中大量 `dxgkio_query_adapter_info: Ioctl failed: -22/-2`。
- WSLg 因此回退到 COPY MODE（窗口标题带 `[WARN:COPY MODE]`），此时所有 X11 窗口（连 xclock）内容渲染为纯黑。
- `wsl --shutdown` 重启 WSL 无法恢复，问题在 Windows 侧 GPU-PV 状态，最终修复需要重启 Windows。
- 与渲染配置文件无关：`~/ros2_humble_env.sh`、`.bashrc`、`/etc/environment` 均已核对，未被改动。

### 排查关键命令

```bash
# 板端（WSL 内）检查 GPU 直通错误
dmesg -T | grep -i dxg

# 检查 WSLg 是否回退 COPY MODE（观察窗口标题是否带 [WARN:COPY MODE]）
```

### 绕过方案（已部署）

VcXsrv 显示不经过 WSLg 的 RDP/D3D12 通道，因此不受 GPU-PV 故障影响：

```powershell
powershell -ExecutionPolicy Bypass -File F:\robot_arm_atlas\ros2\start_so101_display_vcxsrv.ps1
```

新增脚本：

```text
F:\robot_arm_atlas\ros2\start_so101_display_vcxsrv.ps1   一键启动 VcXsrv :1 + display.launch.py
F:\robot_arm_atlas\ros2\run_so101_display_vcxsrv.sh      WSL 侧显示环境（DISPLAY=:1、Zenoh 域 42）
```

该方案与 MoveIt 的 `start_so101_moveit_vcxsrv.ps1` 相同思路，但保留域 42 + Zenoh 客户端配置，因此 `/joint_states` 仍从开发板正常到达。验证结果：RViz 正常渲染（OpenGL 4.2），机械臂模型完整显示且关节实时更新。

### 注意

- VcXsrv 方案是绕过，不是根治。重启 Windows 后应再次尝试 WSLg 路径，确认 dxg 错误消失后即可恢复原来的 `ros2 launch so101_description display.launch.py`。
- 运行 VcXsrv 方案前无需手动停止其他程序，但 RViz 需要 `/joint_states` 数据时，开发板必须先启动只读桥接服务：

```bash
systemctl start so101-rviz-bridge.service
```

## 15. Gazebo 的当前状态

Gazebo 11 已安装在 WSL PC 端，但本次重点是显示真实机械臂状态，因此当前运行链路不需要 Gazebo。

RViz2 是“数据和状态可视化工具”；Gazebo 是“带物理、碰撞、重力和传感器的仿真器”。要在 Gazebo 中仿真 SO-ARM101，还需要继续添加：

1. 碰撞模型和惯性参数校验。
2. Gazebo 插件。
3. `ros2_control` 硬件接口和控制器。
4. 仿真世界、相机和控制启动文件。

因此现在可以在 RViz2 看真实从臂实时状态，但还不能直接用当前包进行完整 Gazebo 动力学仿真。

## 16. 安全规则

1. 实机运行前清空机械臂工作空间。

3. 确认主臂和从臂串口识别没有反向。

## 16.1 在 RViz/MoveIt 中控制真实机械臂（2026-08-15 新增）

### 架构

MoveIt 规划运行在 PC（WSL）侧，轨迹执行由开发板完成：

```text
WSL: RViz + move_group（域42 + Zenoh 客户端）
   │  FollowJointTrajectory action
   ▼
开发板: so101-command-bridge.service（rclpy action server → UDP 15001）[新增]
   │  UDP 15001（目标关节角度，arm 用度、gripper 用 percent）
   ▼
开发板: so101-command-executor.py（SO101Follower.send_action → 串口）[新增]
   ▼
SO-ARM101 从臂
```

开发板 `so101-joint-bridge`（UDP 15000 → `/joint_states`）继续负责实时状态回传，与命令下行互不冲突。

### 开发板启动（按顺序）

```bash
# 1. 只读关节状态桥（若旧服务在运行需先停止以释放从臂串口，然后单独启动 UDP 转发端）
systemctl stop so101-rviz-bridge.service
setsid /root/lerobot_project/start_so101_joint_bridge.sh &   # 仅 UDP 15000 → /joint_states

# 2. 命令桥（systemd 服务，可开机自启）
systemctl start so101-command-bridge.service

# 3. 命令执行器（默认运动门控关闭，安全）
setsid /opt/lerobot061/bin/python /root/lerobot_project/so101_command_executor.py &
```

### PC（WSL）启动

```powershell
# WSLg 正常时：source ~/ros2_humble_env.sh 后直接 ros2 launch so101_moveit_config real_arm.launch.py
# WSLg 故障时（当前）用 VcXsrv：

```

### 开启运动

executor 默认 `motion_enabled=False`，必须显式发送 enable：

```bash
ssh -i C:\Users\98384\.ssh\codex_robot_arm_ed25519 root@192.168.0.2 \
  'python3 -c "import socket,json;s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM);s.sendto(json.dumps({\"cmd\":\"enable\",\"on\":True}).encode(),(\"127.0.0.1\",15001))"'
```

### RViz 操作

1. MotionPlanning 面板选择规划组 `arm`，Start State 选 `current`；
2. 拖拽末端交互标记设定目标，或选命名姿态（`home`/`ready`）；
3. 点击 `Plan` 预览紫色轨迹，确认后点 `Execute` 或 `Plan & Execute`；
4. 夹爪测试切换到规划组 `gripper`，目标 `open`/`closed`。

### 安全措施

- executor 每次 `send_action` 受 `max_relative_target` 限幅（主体 10°/次、夹爪 20%/次）；
- 所有目标经过硬限位校验（实测可达范围），越界立即拒绝并报告；
- 轨迹起始点与当前姿态偏差 >45° 时 bridge 拒绝执行；
- 运动门控默认关闭，需显式 enable；
- `{"cmd":"stop"}` 清空全部轨迹并保持扭矩（不卸力坠落）；
- 网页/终端 `Ctrl+C` 正常退出时断开并卸力。
