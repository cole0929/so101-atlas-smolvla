# 模块 6：抓取篇 —— 相机标定与视觉抓取

> 学完本篇你能回答：机械臂怎么「看见」物块？标定是干什么的？抓取闭环怎么跑通？

## 1. 本篇目标

- 理解相机内参、外参、畸变、eye-in-hand / eye-to-hand 这些概念
- 理解手眼标定的原理（为什么摆多个姿态拍照）
- 理解物块定位的原理（像素 → 3D 坐标）
- 理解 IK（逆运动学）和插值执行
- 能说出本项目的标定结果数值和抓取流程

## 2. 一句话版本

> 机械臂要抓物块，得先知道「相机看到的像素」对应「机器人坐标系里的哪个点」。
> 我们用棋盘格给两个相机做了标定（内参 + 外参），让相机能算距离；
> 然后用颜色检测找到黄色物块，算出它在机械臂底座坐标系里的位置；
> 再用逆运动学算出六个关节该转到多少度，插值安全地执行下去，完成抓取。

## 3. 背景故事：为什么需要标定

### 3.1 相机只是「像素」，不是「坐标」

相机拍到一张 640×480 的图，上面每个像素就是「哪个位置亮什么颜色」。但机械臂要抓的是**三维空间里的点**——物块在桌面上 x、y、z 多少厘米？像素和厘米之间没有天然对应关系，必须靠**标定**建立桥梁。

### 3.2 本项目为什么用两个相机

- **前置相机（俯视固定）**：视野大，能看到整个工作区，但精度一般 → 负责「物块大概在哪」
- **手眼相机（装在夹爪上）**：视野小但离物块近，精度高 → 负责「对准后精确定位」

先粗定位过去，再精定位抓取——这就是「两级定位」策略。

### 3.3 为什么标定这么难（本项目踩坑最多的环节）

标定就是把相机和机器人两个坐标系「焊」在一起，方向差一点、符号错一个，误差就是十几厘米。本项目在这里踩了最多的坑（后面 §6 细讲）。

## 4. 核心概念（大白话 + 面试版）

| 概念 | 大白话 | 面试怎么讲 |
|---|---|---|
| **相机内参** | 描述「像素 ↔ 相机里 3D 点」对应关系的一组数（焦距、光心），每台相机出厂不同 | 相机自身成像属性，用已知几何图案（棋盘格）反推 |
| **相机外参** | 相机坐标系在机器人坐标系里的位置和朝向（4×4 矩阵） | 连接相机和机器人两个坐标系的桥梁 |
| **畸变** | 镜头边缘让直线变弯，去畸变把它拉直 | 径向/切向畸变参数，多角度棋盘格照片估计 |
| **eye-in-hand** | 相机装在手腕上随臂动 → 标定「相机→末端」 | 用 OpenCV `calibrateHandEye`，解 AX=XB |
| **eye-to-hand** | 相机固定在工作区上方俯视 → 标定「相机→底座」 | OpenCV 不支持，用几何法（solvePnP） |
| **solvePnP** | 已知一些点「3D 位置 + 像素位置」，反推相机位姿 | PnP 问题：3D-2D 对应点求相机外参，单张图即可 |
| **手眼标定** | 机械臂摆多个姿态，比较「末端动了多少」和「棋盘格在画面里动了多少」，解出相机↔末端固定变换 | 本质是 AX=XB 矩阵方程，多姿态保证有解 |
| **FK / IK** | FK：关节角→末端位置（容易）；IK：末端位置→关节角（可能无解/多解） | FK 链式矩阵相乘；IK 用阻尼最小二乘处理冗余 |
| **包围盒检测** | 图像里框出物体的矩形框 | HSV 颜色分割 + 轮廓最小外接矩形 |
| **base_link** | 机械臂底座坐标系，全系统的原点 | 所有传感器坐标最终统一到它 |
| **gripper_frame_link** | 夹爪上的标定参考点（在夹爪下方 ~9.8cm，不是咬合点） | IK 和手眼标定的参考点，抓取时需折算 |

## 5. 完整流程（8 步，每步做什么 + 为什么）

### 步骤 1-2：采集标定图 → 标内参

```bash
# 板端执行（示例，真实脚本为 16/17/18 号）
cd /root/lerobot_project
/opt/lerobot061/bin/python 16_capture_calibration.py   # 机械臂摆 15 姿态，两相机拍棋盘格
/opt/lerobot061/bin/python 18_capture_front_intrinsics.py  # 前置相机手持拍 18 张多角度
/opt/lerobot061/bin/python 17_handeye_calibrate.py     # 手眼标定
```

**为什么**：手眼标定要多姿态才有解；内参要多角度才准。棋盘格是「已知 3D 点 + 已知像素点」的标准标定板。

### 步骤 3-4：外参标定

- **前置相机（几何法）**：棋盘格平放桌面、位置实测已知 → 角点直接建在 base 系 → `solvePnP` 一次求解 → `T_cam2base = [R.T | -R.T·t]`
- **手眼相机**：FK 算末端位姿 + solvePnP 算棋盘格位姿 → `calibrateHandEye`（Tsai 法）解 camera→gripper

**为什么分两种**：eye-to-hand 没有现成 OpenCV 函数；eye-in-hand 有现成的（`calibrateHandEye`）。

### 步骤 5：物块定位

```text
拍图 → HSV 找黄色 → 质心/包围盒 → 去畸变 → 像素变射线 → 射线与桌面(z=0)求交 → 物块在 base 系的 (x,y)
```

**为什么这样算**：单目相机一个像素只给「方向」不给「距离」。靠「物块在桌面上」这个先验，让射线和桌面平面求交，就能补出深度。

### 步骤 6：IK 解算

```bash
/opt/lerobot061/bin/python ik_solver.py   # 阻尼最小二乘 + 关节限位 + 线搜索
```

从「自然前伸姿态」出发迭代（**关键**：零位姿态会陷入局部最优，误差 18cm → 好初始猜测误差 0.0cm）；再扫描 wrist_flex 让夹爪垂直朝下。

### 步骤 7-8：插值执行 + 夹取

```bash
/opt/lerobot061/bin/python 20_grasp_block.py --dry-run    # 先只打印计划
/opt/lerobot061/bin/python 20_grasp_block.py \
  --handeye-offset-y +0.05 \
  --jaw-clearance 0.04
```

执行策略：粗定位到物块上方（approach 高度 0.20m）→ 手眼相机精定位 → 下降 → 下爪对准物块下边缘外侧 → 闭合 → 抬起。

## 6. 踩过的坑（真实记录，面试加分项）

| 坑 | 原因 | 解决 |
|---|---|---|
| `calibrateHandEye` 用错 | OpenCV 只支持 eye-in-hand，强行解 eye-to-hand 全错 | 改用几何法（solvePnP） |
| 外参偏 16cm | 组合 R.T 时多加了一步 `T_b2base` 平移 | 用 `[R.T \| -R.T·t]`，不多加 |
| Z 轴方向 | 俯视相机光轴必须朝下 | 用 Ry(π) 翻转，验证 cam_z>0.05 |
| 标定「看起来对」实际错 | 只看重投影误差，没做反投影自检 | 棋盘格中心反投影回实测坐标应分毫不差 |
| IK 掉局部最优 | 零位初始姿态 | 从「自然前伸姿态」出发 |
| 一步执行不到位 | `send_action` 单步限幅 10° | 插值多步执行（`--max-relative-target` 30°） |
| 下爪戳物块中心 | gripper_frame_link 不是物理咬合点 | `--jaw-clearance` 让下爪在物块下边缘外侧 |

## 7. 面试怎么讲（1 分钟版）

> 视觉抓取部分，我们采用双相机两级定位方案：前置固定相机（eye-to-hand）
> 用几何法标定外参（solvePnP + 反投影自检），负责粗定位物块；
> 夹爪上的手眼相机（eye-in-hand）用 OpenCV calibrateHandEye 标定，
> 负责接近后的精定位。像素坐标通过「像素→射线→桌面求交」反投影到
> base_link 坐标系，再用阻尼最小二乘的数值 IK 解算关节角，
> 通过限幅插值安全执行。整个流程实测定位误差 ≤1.5cm。
> 这个环节我最大的收获是踩了很多标定的坑——比如 eye-to-hand 不能
> 用 calibrateHandEye、外参矩阵的方向约定、标定结果必须反投影自检，
> 这些经验让我对坐标系变换理解很深。
