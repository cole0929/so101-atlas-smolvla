# 模块 5：孪生篇 —— ROS2 数字孪生

> 学完本篇你能回答：数字孪生是什么？ROS2 怎么把机械臂「搬」进电脑？跨机通信怎么做到？

---

## 1. 本篇目标

- 理解 ROS2 的核心概念（节点、话题、消息、TF、URDF）
- 理解数字孪生的原理（真实关节角 → 虚拟模型实时同步）
- 理解 Zenoh/rmw 跨机通信（开发板 ↔ WSL2）
- 理解 robot_state_publisher、RViz2、MoveIt2 各干什么
- 能说出数据流链路和关键命令

## 2. 一句话版本

> 开发板读真实机械臂的关节角度，转成 ROS2 消息（/joint_states），
> 通过 Zenoh 跨网络送到 Windows 的 WSL2，
> 电脑上的 robot_state_publisher 按 URDF 模型算出每个零件的坐标，
> RViz2 把它们画出来——于是电脑里出现一只和真机同步动作的
> 3D 机械臂，这就是数字孪生。MoveIt2 负责反过来：在电脑上
> 规划动作，下发控制真实机械臂。

## 3. 背景故事：为什么需要数字孪生

### 3.1 你看不见机械臂在干嘛

机械臂在工作区执行任务时，人不可能盯着每个关节看。数字孪生 = 把机械臂的实时状态「镜像」到电脑上：

- 实时显示每个关节的角度、末端位置
- 叠加工作区边界、禁入区（安全监控）
- 显示物块定位结果（视觉在 RViz 里可视化）
- 为 MoveIt2 规划提供环境（规划好了再下发执行）

### 3.2 为什么用 ROS2

ROS2 是机器人领域的事实标准框架：节点（程序）、话题（通信）、消息（数据格式）都是现成的，机械臂状态、TF 坐标树、可视化 Marker 都有标准消息类型，跨机器也能通信。用 ROS2 = 站在生态上，不用自己造轮子。

### 3.3 为什么分「开发板」和「PC」两端

- 开发板：接硬件（串口、相机），算力有限 → 只装精简版 `ros-base`，不做可视化
- PC（WSL2）：装 `ros-desktop`（RViz2、Gazebo），图形渲染放这里

两端通过 **rmw_zenoh_cpp** 通信——Zenoh 就是 ROS2 的「快递公司」。

## 4. 核心概念（大白话 + 面试版）

| 概念 | 大白话 | 面试怎么讲 |
|---|---|---|
| **ROS2** | 机器人各模块互相说话的消息总线 | 机器人分布式通信框架，节点间话题发布/订阅 |
| **节点** | 一个干一件事的程序进程 | 独立进程、单一职责、可跨机器分布 |
| **话题/消息** | 广播频道 + 频道里跑的数据格式 | 异步 pub/sub 通道 + 类型化数据结构 |
| **URDF** | 机器人的说明书（XML）：几节、关节在哪、长啥样 | 描述运动学模型和可视化网格 |
| **TF 坐标树** | 各零件坐标关系（谁在谁的哪一侧） | 维护坐标系树，渲染和坐标换算的基础 |
| **RViz2** | 把模型和数据画出来的 3D 可视化工具 | ROS2 可视化工具，显示模型/轨迹/Marker |
| **MoveIt2** | 规划「末端从 A 到 B 怎么走」的运动库 | 运动规划，输出关节轨迹 |
| **数字孪生** | 真实机械臂在电脑里的实时镜像 | 真实关节数据驱动虚拟模型，虚实同步 |
| **Zenoh/rmw** | ROS2 的「快递公司」 | rmw 是通信抽象层，Zenoh 实现跨机低延迟 |
| **domain ID** | 快递分区号，同号互通、异号隔离 | ROS_DOMAIN_ID 隔离不同 ROS2 系统 |
| **robot_state_publisher** | 读关节角 → 按 URDF 算每个零件的坐标（发 /tf） | 把 joint_states 转成 TF 树 |
| **joint_states** | 每个关节当前角度的标准消息 | sensor_msgs/JointState |

## 5. 完整数据流（背下来，面试画图用）

```text
上行（状态 → 显示）：
机械臂(串口) → 开发板 LeRobot 读关节角
  → so101_joint_bridge 转 /joint_states（UDP 15000）
  → Zenoh 路由器（192.168.0.2:7447）跨机搬运
  → WSL2 rmw_zenoh_cpp 收到
  → retime 重打时间戳（修时钟差）
  → /joint_states_local
  → robot_state_publisher 算 TF
  → RViz2 显示数字孪生

下行（规划 → 控制）：
RViz2 MotionPlanning → move_group 发轨迹
  → 开发板 command-bridge（UDP 15001）
  → command-executor（限幅/硬限位/运动门控，默认关）
  → 串口 → 从臂电机
```

## 6. 实际操作（有真机可做）

```bash
# 板端：启动只读桥接（发布真实关节状态）
ssh root@192.168.0.2
systemctl start so101-rviz-bridge.service
# 或手动：/root/lerobot_project/start_so101_rviz_bridge.sh

# WSL2 端：一键启动数字孪生（含叠加层）
source ~/ros2_humble_env.sh
ros2 launch so101_visualization trajectory_viz.launch.py

# 看话题和频率（验证数据在流动）
ros2 topic list                    # 应看到 /joint_states /tf /dt_boundary 等
ros2 topic hz /joint_states        # 应看到约 10~30 Hz
ros2 topic echo /joint_states --once  # 看最新关节角度

# 重要：WSL + Zenoh 必须停 daemon
ros2 daemon stop
```

数字孪生叠加层（`digital_twin_layers.py`，用 RViz Marker 消息）：

| 图层 | 话题 | 内容 |
|---|---|---|
| 工作区边界 | `/dt_boundary` | 半透明绿色盒 = 实际工作空间 |
| 禁入区 | `/dt_forbidden` | 红色薄墙（2cm）= 不可越过的边界 |
| 关节角度标注 | `/dt_joint_labels` | 六关节实时角度文字 |
| 状态快照 | `/dt_stats` | 关节角度 JSON |

物块定位显示（另一条链路）：板端相机检测 → 写 `located_object.json` → Windows 脚本 scp 拉取 → WSL bridge 发 `/located_object` → RViz 显示黄球 + 坐标文字。

## 7. 踩过的坑（真实记录）

| 坑 | 解决 |
|---|---|
| WSL 的 ros2 daemon 与 Zenoh 不兼容，查不到数据 | `ros2 daemon stop`（CLI 走直连） |
| 开发板/WSL 时钟偏差导致模型闪烁 | retime 节点重打时间戳 |
| WSLg GPU 直通故障黑屏 | 用 VcXsrv 显示（软件渲染） |
| 只读桥与遥操作抢从臂串口 | 互斥使用，桥接不开机自启 |
| `colcon build` 报安装布局错误 | 加 `--merge-install` |
| Conda Python 3.9 误加载 rclpy | 桥接固定 `/usr/bin/python3` |
| WSL NAT 发现不了板端 | 板端跑 Zenoh TCP 路由（7447） |

## 8. 面试怎么讲（1 分钟版）

> 数字孪生部分，我们基于 ROS2 Humble 搭建：开发板通过 LeRobot
> 读取从臂真实关节角，转成 /joint_states 话题，经 rmw_zenoh_cpp
> 跨机传输到 PC 的 WSL2——开发板运行 Zenoh TCP 路由器监听
> 192.168.0.2:7447，两端用相同的 ROS_DOMAIN_ID。
> PC 端 robot_state_publisher 按官方 URDF 模型把关节角转成 TF 坐标树，
> RViz2 实时渲染，实现与真机同步的数字孪生；我们还用 Marker
> 叠加了工作区边界、禁入区、关节角度标注等图层做安全监控；
> 下行方向用 MoveIt2 规划轨迹，经 command bridge 下发控制真实机械臂。
> 这里比较典型的工程问题是跨机时钟偏差导致模型闪烁，
> 我们通过重打时间戳解决，还有 WSL 下 zenoh 与 ros2 daemon 的兼容问题。
