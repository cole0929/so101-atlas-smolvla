## 3. 30 秒电梯演讲（背这个）

> 这个项目是用 AI 让机械臂「看、听、动」一体的完整闭环。
> 我们以开源 SO-ARM101 六轴机械臂为硬件，先通过遥操作录了

## 4. 关键技术点逐条答（面试官可能深挖）

### 4.1 为什么用 SmolVLA？为什么不用大模型？

- 目标平台是开发板 NPU，算力有限 → 需要小模型
- SmolVLA 约 0.5B 参数，能部署到 310B1，实测一次推理 ~918ms，实时可控
- 这是「能力 vs 算力」的权衡，也是边缘部署的核心考量

### 4.2 为什么模型要拆 4 个子图？

- 整模型导出 ONNX/转 OM 会失败（算子不支持、内存不足）
- 按功能拆：vision（图像）、state_proj（状态）、prefix（语言前缀）、denoise（动作）
- 每个子图单独转换、单独 golden case 验证，最后运行时串联
- 方法论：分而治之 + 全程验证（从 matmul 冒烟测试起步）

### 4.3 ONNX / OM / ATC / pyACL 各是什么？

- ONNX：模型通用交换格式（模型界的 JPEG）
- ATC：华为编译工具，把 ONNX 编译成 NPU 可执行的 OM
- OM：NPU 专属模型文件
- pyACL：Ascend 计算库的 Python 接口（运行时驱动）；AclLite 是其封装

### 4.4 数字孪生怎么做？

- 真实关节角 → /joint_states 话题 → Zenoh 跨机 → robot_state_publisher 转 TF → RViz2 渲染
- 用 URDF 描述模型，用 Marker 叠加边界/禁入区/角度标注
- 关键工程点：跨机时钟偏差重打时间戳、Zenoh 与 ros2 daemon 兼容

### 4.5 相机标定怎么做？两个相机区别？

- 前置（eye-to-hand）：几何法，solvePnP + 反投影自检（OpenCV 不支持该模式）
- 手眼（eye-in-hand）：OpenCV calibrateHandEye，解 AX=XB
- 内参标定：棋盘格多角度，重投影误差 0.74px（前置）/ 0.46px（手眼）

### 4.6 单目相机怎么算距离（深度）？

- 一个像素只给方向，不给距离
- 靠「物体在桌面 z=0 平面」的先验：像素 → 射线 → 与平面求交 → 3D 坐标

### 4.7 IK 怎么做？难点？

- 数值 IK：阻尼最小二乘 + 关节限位 + 线搜索
- 难点：初始姿态决定收敛（零位 → 18cm 误差；自然前伸 → 0.0cm）
- 抓取朝向：扫描 wrist_flex 让夹爪垂直朝下

### 4.8 安全怎么保证？

- 限幅（主体 10°、夹爪 20°/步）+ NaN/Inf 拦截 + 网页 SAFE STOP
- 结束自动回位；observe 模式默认不发动作，运动需显式 `--motion-key`
- 软件停止不能替代物理断电；运行时工作区不得有手/脸/线缆

## 6. 踩坑故事（讲 2-3 个，比背书更有说服力）

### 故事 1：标定的「看起来对」
前置相机标定用 calibrateHandEye 硬解 eye-to-hand，结果全错；
外参组合时多加一步平移，棋盘格反投影偏 16cm。
**教训**：eye-to-hand 没有现成函数，用几何法；标定必须做反投影自检，
不能只看重投影误差。

### 故事 2：一步到位的猛冲
目标关节角差 82°，send_action 默认限幅 10°/步，一次下发根本不到位。
**教训**：舵机有速度极限，必须插值多步执行；限幅是安全第一原则。

### 故事 3：数据质量 > 算法
内参标定数据重采后，误差从 6.4px 降到 0.74px。
**教训**：数据是机器学习的天花板，脏数据再好的算法也救不回来。

### 故事 4：NPU 迁移的「分而治之」
整模型导出失败 → 拆 4 子图；每个子图先跑 matmul 冒烟，再 CPU/NPU 对比。
**教训**：复杂部署要拆分验证、逐步推进，不能一把梭。

## 7. 可能的追问与应对

| 追问 | 怎么答 |
|---|---|
| 「你自己写代码了吗？」 | 诚实 + 强调理解：项目由 AI 辅助完成，我负责架构理解、调试、参数调优，这套教程就是我把全链路吃透的过程 |
| 「项目有什么不足？」 | 语言指令是固定 embedding，不支持任意自然语言；抓取未完全调通（y 偏差）；数据量小泛化有限；动作块同步推理有交接点停顿——下一步规划数据扩展 + 仿真 RL + 双缓冲流水线（详见 [08_优化方向与遗留问题](08_优化方向与遗留问题.md)） |
| 「RL 加过吗？」 | 尚未加入；规划是仿真环境（Isaac/Gazebo）域随机预训练 → sim2real → 真机 RLVR 微调（详见 [08_优化方向与遗留问题](08_优化方向与遗留问题.md)） |
| 「为什么不用现成抓取库？」 | 学习导向：手写 IK、几何法标定，深入理解原理；同时说明用 MoveIt2 做规划 |
| 「30Hz 和 20Hz 为什么换？」 | 高频 + 多步去噪导致轨迹锯齿，改 20Hz/5 步去噪后平滑 |
