## 1. 本篇目标

- 理解 LeRobot 是什么、管哪些环节
- 理解 episode、频率（20Hz）、帧这些数据集概念
- 理解双相机采集 + 关节状态记录为什么是一套组合

## 2. 一句话版本

> 我们让人握着 Leader 主臂做「抓起黄块放进黑盒」的动作（叫示教），
> 同时用两个相机录像、记录从臂每个关节的角度，
> 以每秒 20 帧存成一段段演示（叫 episode），
> 凑齐 50 段、8453 帧，组成训练数据集。
> 这套「录示范 → 让模型模仿」的流程，是 LeRobot 框架管的事。

## 3. 背景故事：为什么需要数据

### 3.1 机器学习两条路：规则 vs 模仿

- **规则编程**：程序员写死「物块在 (x,y) 就转到角度 θ」——写不全面，场景一变就失效
- **模仿学习（本项目）**：不做动作，只录人类示范，让模型自己学「看到什么画面 + 什么指令 → 动什么」

模仿学习的核心资产就是**数据**：数据质量决定模型上限（本项目一个深刻教训：内参标定数据质量差 8 倍，重标后误差从 6.4px 降到 0.74px——数据 > 算法）。

### 3.2 LeRobot 是什么

LeRobot 是 HuggingFace 的开源机器人学习框架，管四件事：

```text
数据采集 → 数据清洗 → 模型训练 → 模型推理
```

本项目用它走完了全流程（板端 `/opt/lerobot061` 环境就是装它的）。

### 3.3 为什么是「双相机 + 关节角度」

模型要模仿人类动作，需要知道三件事：

| 信息 | 从哪来 | 作用 |
|---|---|---|
| **看到什么** | 双相机画面（前置全局 + 手眼局部） | 视觉输入 |
| **要做什么** | 一句任务指令（英文） | 语言输入 |
| **现在什么样** | 六关节当前角度 | 状态输入 |

三者合在一起，模型才能学会「看到 A、听到指令 B、当前状态 C → 应该动到 D」。

## 4. 核心概念（大白话 + 面试版）

| 概念                     | 大白话                                 | 面试怎么讲                               |
| ---------------------- | ----------------------------------- | ----------------------------------- |
| **VLA**                | 看一眼 + 听一句 → 输出动作的模型                 | Vision-Language-Action 模型，视觉语言动作一体化 |
| **示教/遥操作**             | 人握着 Leader 动，Follower 跟着动并记录        | 遥操作采集示范数据，模仿学习的基础                   |
| **episode**            | 一次完整的演示（从开始到结束的一段记录）                | 一个 episode = 一次完整的任务演示序列            |
| **帧 (frame)**          | 一帧 = 某一时刻的「画面 + 关节角度」快照             | 时间步采样，包含多模态观测                       |
| **20Hz**               | 每秒记录 20 帧（相邻帧动作最大跳变约 25°）           | 采样频率决定动作粒度                          |
| **动作块 (action chunk)** | 模型一次预测未来 50 帧 × 6 关节 = 一份「5 秒动作计划表」 | 预测未来多步动作，减少累积误差                     |
| **embedding**          | 把一句话翻译成数字向量，让模型能「读懂」指令              | 语言指令的向量表示（本项目固定 48 token）           |
| **rollout**            | 让模型自己连续执行完整任务的过程                    | 模型自主执行推理并控制机械臂                      |

## 5. 实际操作（有真机可做）

```bash
# 板端进入 LeRobot 环境
ssh root@192.168.0.2
source /opt/lerobot061/bin/activate   # 或直接用 /opt/lerobot061/bin/python

# 查看采集到的数据集（本项目真实数据）
cd /root/lerobot_project/datasets/admin
ls smolvla_yellow_block_atlas_v2_clean/   # 数据集目录
```

看数据集目录里有什么（重点理解概念）：

| 内容 | 说明 |
|---|---|
| `episodes/` | 50 段演示，每段一个文件 |
| `videos/` | 双相机录的原始视频（每段有两个视角） |
| `meta/` | 每帧的关节状态、时间戳等元数据 |
| `info.json` | 数据集配置（频率、相机、关节定义） |

> 真实参数：20Hz、50 episodes、总帧数 8453、任务指令
> 「Pick up the yellow block, place it inside the black box, release it, then return the arm to its starting position.」

## 6. 踩过的坑（真实记录）

| 坑 | 解决 |
|---|---|
| 初版采样 30Hz + 10 步去噪 → 轨迹锯齿 | 改 20Hz 采样、5 步去噪后平滑 |
| 数据里夹带空/异常 episode | 数据清洗剔除，统一格式 |
| 板端采集环境被后续部署污染 | 独立环境 `/opt/lerobot061`，NPU 实验另建 `/opt/smolvla_npu_test` |
| `/dev/video1/3` 是 metadata 节点不能用 | 按 USB PID 动态识别相机，不写死节点号 |
| 相机映射会变 | 前置 9221 → video0，手眼 9005 → video2（以实机 ls 为准） |

## 7. 面试怎么讲（1 分钟版）

> 数据部分，我们用 LeRobot 框架通过遥操作采集示范数据：
> 人操作主臂完成抓取任务，双相机录像 + 记录从臂六关节状态，
> 以 20Hz 采样，共采集 50 个 episode、8453 帧，
> 任务指令是固定的英文句子（抓黄块放进黑盒再回位）。
> 采集时我体会到数据质量比算法更重要——比如内参标定数据
> 重采后误差从 6.4px 降到 0.74px。数据是模仿学习的天花板，
> 所以数据清洗和多样性设计是重中之重。
