# 模块 1：硬件篇 —— 机械臂与开发板

> 学完本篇你能回答：这套系统里都有哪些硬件？各自干什么？怎么连起来的？

---

## 1. 本篇目标

- 认识 SO-ARM101 机械臂（Leader/Follower 是什么、6 轴是哪 6 轴）
- 认识 Atlas 200I DK A2 开发板和 Ascend 310B1 NPU
- 知道串口、USB 相机、网络连接是怎么回事
- 能说出「为什么需要一个开发板来当大脑」

## 2. 一句话版本

> 一套系统 = 两台 SO-ARM101 机械臂（人示教的 Leader + 干活的 Follower）
> + 一台华为 Atlas 200I DK A2 开发板（上面有 NPU，跑模型推理）
> + 两个 USB 相机（前置俯视 + 夹爪上的手眼）
> + 一台 Windows PC（显示数字孪生）。
> 开发板通过串口控制机械臂，通过 USB 读相机，通过网络（192.168.0.2）和 PC 通信。

## 3. 背景故事：为什么这么配

### 3.1 机械臂：SO-ARM101

SO-ARM101 是**开源 6 轴机械臂**。6 轴 = 6 个关节（肩、肘、腕等），每个关节一个舵机（电机+减速器），可以转一定角度。6 个关节组合起来，末端（夹爪）就能到达三维空间任意位置和姿态。

这个项目用**两台**：

| 角色 | 名字 | 干什么 |
|---|---|---|
| Leader（主臂） | 教师臂 | 人握着它做动作，它把关节角度记录下来（示教） |
| Follower（从臂） | 学生臂 | 接收命令，执行动作（真正干活的） |

两个臂各有一个 USB 序列号（Follower: `5C82108953`，Leader: `5C4C123788`），这样程序能区分它们。项目里自主推理时**只用 Follower**，Leader 用于示教采集。

> 类比：Leader 是老师的手在示范，Follower 是学生的手在模仿。

### 3.2 开发板：Atlas 200I DK A2

「DK」= Developer Kit（开发套件）。这是一块华为的 AI 开发板：

- **CPU**：4 核 ARM（aarch64 架构）
- **NPU**：Ascend 310B1（AI 推理芯片，专门加速神经网络）
- 跑 **Ubuntu 22.04**（Linux 系统）
- 地址 `192.168.0.2`，主机名 `davinci-mini`

**为什么需要它？** 因为 SmolVLA 这种「视觉-语言-动作」大模型推理很重，普通单片机跑不动，需要 NPU 加速。板子 + NPU = 机械臂自带的「大脑」，**不依赖 PC 也能自己干活**。

> 类比：开发板像机械臂的「随身电脑 + 显卡」，模型推理就在板子上完成。

### 3.3 相机：两个 USB 相机

| 相机 | 装在哪 | 干什么 | 设备标识 |
|---|---|---|---|
| 前置相机 | 固定俯视工作区（eye-to-hand） | 看全局，定位物块大概位置 | USB PID `9221` |
| 手眼相机 | 装在夹爪上（eye-in-hand） | 精定位，看物块细节 | USB PID `9005` |

> ⚠️ 注意：项目文档里相机 ↔ `/dev/video*` 的映射出现过两种说法（有的写前置 9221→video0/手眼 9005→video2，有的反过来）。
> `/dev/video1/3` 还是 metadata 节点不能当图像用。
> **正确做法是按 USB PID 动态识别相机，不要写死节点号**——以实机 `ls /dev/video*` + PID 检查结果为准。

- **eye-to-hand**：相机固定在外部看手 → 相当于「天上的监控」
- **eye-in-hand**：相机装在手上跟着动 → 相当于「手上的眼睛」

两个相机都 640×480 RGB，采集时前置用 MJPG 压缩、手眼降分辨率，否则 USB 带宽不够（踩过的坑）。

### 3.4 PC：Windows + WSL2

PC 不参与推理，只干三件事：显示数字孪生（RViz2）、SSH 操作板子、跑 MoveIt2 规划。

## 4. 核心概念

| 概念 | 大白话 |
|---|---|
| **串口** | 板子和机械臂之间的通信线（USB 转串口），一条线传命令、一条传状态 |
| **关节角度** | 每个舵机当前转的角度，6 个角度 = 机械臂的一个「姿态」（joint_states） |
| **aarch64/ARM** | 开发板的 CPU 架构，和普通电脑 x86 不同，软件要装 ARM 版 |
| **NPU** | 神经网络处理单元，专门算矩阵乘法，比 CPU 快几百倍 |
| **PID** | USB 设备的厂商标识，用来区分两个相机 |
| **/dev/video0** | Linux 里相机的「门牌号」 |
| **DHCP/静态 IP** | 板子固定用 192.168.0.2，PC 通过这个地址 SSH 上去 |

## 5. 实际操作（有真机可做）

```bash
# 1. SSH 登录开发板（在 Windows 终端或 MobaXterm）
ssh root@192.168.0.2

# 2. 看板子系统信息
uname -a                      # 应该是 aarch64 / Ubuntu
cat /etc/os-release | head -2 # 确认 Ubuntu 22.04

# 3. 看 NPU 状态（确认推理芯片在工作）
npu-smi info                  # 能看到 Ascend 310B1 的温度、使用率

# 4. 看相机设备
ls /dev/video*                # 应看到 video0(前置) video2(手眼)

# 5. 看串口设备（机械臂）
ls /dev/ttyUSB* /dev/ttyACM*  # 应看到两个机械臂的串口
```

> 预期结果：每一条命令都能看到对应硬件。如果 `npu-smi` 没有，说明 CANN 环境没配好（模块 4 会讲）。

## 6. 踩过的坑（本项目真实记录）

| 坑 | 原因 | 解决 |
|---|---|---|
| 双相机同时读失败 | USB 带宽不足 | 前置用 MJPG 压缩、手眼降分辨率 |
| 板端 ros2 命令找不到 | 没 source ROS 环境 | 先 `source ~/ros2_humble_env.sh` |
| 板端 Python 没有 rclpy | lerobot 环境与 ROS 分离 | 视觉/控制用 lerobot 环境，ROS 转发放 WSL |
| 开发板磁盘/内存小 | 硬件限制 | 不装桌面软件，RViz/Gazebo 放 PC 端 |
| 串口被占用 | 遥操作服务和推理同时抢串口 | 服务按需启动，推理时不开桥接 |

## 7. 面试怎么讲

> 硬件方案上，我们选用了开源 6 轴机械臂 SO-ARM101 作为执行本体，
> 用华为 Atlas 200I DK A2 开发板作为边缘计算节点——它内置 Ascend 310B1 NPU，
> 能在板端完成 SmolVLA 的实时推理，做到不依赖 PC 的自主控制。
> 感知上采用双相机方案：前置固定相机做全局定位（eye-to-hand），
> 夹爪上的手眼相机做局部精定位（eye-in-hand），兼顾了视野范围与精度。
