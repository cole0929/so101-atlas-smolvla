## 2. 一句话版本

> SmolVLA 是一个「视觉-语言-动作」模型：给它看一眼画面、听一句指令、
> 知道当前关节角度，它就能输出未来 50 帧、6 个关节的动作计划。
> 它由四个模块组成：视觉编码器（看）、状态投影（读关节）、
> 语言前缀（懂指令）、动作去噪器（出动作）。
> 我们用 50 段示教数据在 A100 上训练它，得到了 020000 检查点。

## 3. 背景故事：为什么用 SmolVLA 而不是别的

### 3.1 为什么是 VLA 而不是「纯视觉 + 规则」

传统抓取：相机定位 → 算坐标 → 程序控制。但它只会这一招。
VLA 的思路：**端到端**——不分开做感知和规划，直接「画面+指令+状态 → 动作」，
模型自己学会理解场景、理解指令、生成动作。泛化性和可扩展性更强。

### 3.2 为什么是 SmolVLA（小模型）

大模型（如 70B）能力强但**跑不动**——我们的目标是部署在开发板的 NPU 上。
SmolVLA 约 0.5B 级参数，小到能装进开发板、能在 310B1 NPU 上实时推理（实测一次完整推理约 918ms）。
这是「能力 vs 算力」的权衡：选一个在边缘设备上能跑的模型。

### 3.3 模型内部：四个模块各管一段

```text
┌─────────────────────────────────────────────────────────┐
│ 图像 512×512 ──> vision（视觉编码器）──> 视觉 token       │
│ 关节状态 6 维 ──> state_proj（补零32→投影960）──> 状态 token│
│ 指令 48 token ──> prefix（语言前缀，预填充 KV cache）      │
│                                                        │
│ 三者汇合 ──> denoise（动作去噪器，5 步流匹配去噪）          │
│              └──> 输出 50×6 动作块（未来5秒动作计划）       │
└─────────────────────────────────────────────────────────┘
```

| 模块 | 大白话 | 输入 → 输出 | 类比 |
|---|---|---|---|
| **vision** | 把图翻译成模型能读的 token | 1×3×512×512 → 64×960 | 看图说话 |
| **state_proj** | 把关节角度整理成模型格式 | 6 维 → 补零 32 → 投影 960 | 传感器读数转表格 |
| **prefix** | 把指令「读进脑子里」并缓存 | 48 token → 16 层 KV prefill | 先记住任务要求 |
| **denoise** | 从噪声一步步还原动作 | 噪声 → 5 步去噪 → 50×6 动作 | 洗照片，越洗越清晰 |

### 3.4 关键机制：KV cache 与动作块

- **KV cache**：模型读指令/看画面时把算过的中间结果存起来，后面生成动作时直接复用，不重复算——这是推理提速的关键
- **动作块（50×6）**：一次预测未来 50 帧的动作，而不是一帧一帧挤牙膏。好处：动作更连贯、执行更稳，也是本项目「一次推理 918ms 驱动 5 秒动作」的设计来源

## 4. 核心概念（大白话 + 面试版）

| 概念 | 大白话 | 面试怎么讲 |
|---|---|---|
| **模仿学习** | 看示范、学动作 | 从专家示教中学习策略（Behavior Cloning） |
| **ONNX** | 模型的通用交换格式，任何框架都能读 | 模型界的 JPEG，跨框架标准格式 |
| **检查点 (checkpoint)** | 训练到某一步保存的模型快照 | 020000 = 训练 2 万步的模型 |
| **流匹配去噪** | 从噪声逐步还原真实动作的过程 | 生成式动作建模，5 步 Euler 采样 |
| **20K steps** | 训练迭代了 2 万步 | 训练量配置 |
| **A100** | NVIDIA 数据中心 GPU（本项目的训练服务器） | 训练阶段算力平台（和部署端 NPU 不同） |
| **sim2real** | 仿真到真实的迁移（本项目未做） | 领域差距问题（后续可扩展方向） |

## 6. 踩过的坑（训练/模型侧）

| 坑 | 解决 |
|---|---|
| CPU 推理一帧要 73 秒，无法实机控制 | 必须部署到 NPU（模块 4） |
| 语言指令是「写死」的 48-token embedding | 改指令不会自动生效；支持新指令需动态 tokenizer（后续工作） |
| Transformers 动态视觉 mask 无法导出 | 固定 512×512、固定 position id、eager attention |
| BF16 权重被装进 FP32 骨架 | `load_state_dict(..., assign=True)` |

## 7. 面试怎么讲（1 分钟版）

> 模型选型上，我们用了 HuggingFace 的 SmolVLA——一个约 0.5B 参数的
> 视觉-语言-动作模型。选择它的核心考量是「能部署到边缘」：
> 它小到可以运行在昇腾 310B1 NPU 上，实测单次完整推理约 918 毫秒，
> 可以实时驱动机械臂。模型内部四个模块——视觉编码器、状态投影、
> 语言前缀、动作去噪器——也决定了我们后续的部署拆分策略。
> 训练采用模仿学习：50 段示教数据、20K 步，产出 020000 检查点。
> 语言指令通过固定的 48-token embedding 输入，这是一处简化，
> 支持任意自然语言指令需要动态 tokenizer，是我们的后续优化点。
