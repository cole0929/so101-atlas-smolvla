## 1. 本篇目标

- 理解 VLA 模型是什么、SmolVLA 为什么叫「小号」VLA

- 理解「训练」在做什么（模仿学习：看示范学动作）

## 2. 一句话版本

> SmolVLA 是一个「视觉-语言-动作」模型：给它看一眼画面、听一句指令、
> 知道当前关节角度，它就能输出未来 50 帧、6 个关节的动作计划。
> 它由四个模块组成：视觉编码器（看）、状态投影（读关节）、
> 语言前缀（懂指令）、动作去噪器（出动作）。
> 我们用 50 段示教数据在 A100 上训练它，得到了 020000 检查点。

## 3. 背景故事：为什么用 SmolVLA 而不是别的

### 3.1 为什么是 VLA 而不是「纯视觉 + 规则」

传统抓取：相机定位 → 算坐标 → 程序控制。但它只会这一招。
VLA 的思路：**端到端**——不分开做感知和规划，直接「画面+指令+状态 → 动作」，
模型自己学会理解场景、理解指令、生成动作。泛化性和可扩展性更强。

### 3.2 为什么是 SmolVLA（小模型）

大模型（如 70B）能力强但**跑不动**——我们的目标是部署在开发板的 NPU 上。
SmolVLA 约 0.5B 级参数，小到能装进开发板、能在 310B1 NPU 上实时推理（实测一次完整推理约 918ms）。
这是「能力 vs 算力」的权衡：选一个在边缘设备上能跑的模型。

### 3.3 模型内部：四个模块各管一段

```text
┌─────────────────────────────────────────────────────────┐
│ 图像 512×512 ──> vision（视觉编码器）──> 视觉 token       │
│ 关节状态 6 维 ──> state_proj（补零32→投影960）──> 状态 token│
│ 指令 48 token ──> prefix（语言前缀，预填充 KV cache）      │
│                                                        │
│ 三者汇合 ──> denoise（动作去噪器，5 步流匹配去噪）          │
│              └──> 输出 50×6 动作块（未来5秒动作计划）       │
└─────────────────────────────────────────────────────────┘
```

| 模块 | 大白话 | 输入 → 输出 | 类比 |
|---|---|---|---|
| **vision** | 把图翻译成模型能读的 token | 1×3×512×512 → 64×960 | 看图说话 |
| **state_proj** | 把关节角度整理成模型格式 | 6 维 → 补零 32 → 投影 960 | 传感器读数转表格 |
| **prefix** | 把指令「读进脑子里」并缓存 | 48 token → 16 层 KV prefill | 先记住任务要求 |
| **denoise** | 从噪声一步步还原动作 | 噪声 → 5 步去噪 → 50×6 动作 | 洗照片，越洗越清晰 |

### 3.4 关键机制：KV cache 与动作块

- **KV cache**：模型读指令/看画面时把算过的中间结果存起来，后面生成动作时直接复用，不重复算——这是推理提速的关键
- **动作块（50×6）**：一次预测未来 50 帧的动作，而不是一帧一帧挤牙膏。好处：动作更连贯、执行更稳，也是本项目「一次推理 918ms 驱动 5 秒动作」的设计来源

### 3.5 denoise 深度解析（动作是怎么「洗」出来的）

**一句话**：denoise（去噪器）不「算」动作，而是**从一团随机噪声里一步步「洗」出动作**——就像显影照片越洗越清晰。这个过程叫**流匹配（flow matching）**，本项目用 5 步 Euler 积分完成。

**为什么动作要靠「去噪」生成，而不是直接算？**

SmolVLA 的动作专家是**生成式模型**（类似画图的扩散模型），不是回归模型：

| | 回归式（传统） | 生成式（SmolVLA 用的） |
|---|---|---|
| 思路 | 直接预测一个确定的动作向量 | 从噪声开始，逐步采样出一个动作 |
| 类比 | 看到菜谱直接写出成品菜的样子 | 看着菜谱凭空想象，越描越具体 |
| 输出 | 唯一确定 | 每次采样可能略有不同（多样性） |
| 优点 | 简单直接 | 能生成自然、多样、连续的动作 |
| 缺点 | 容易平均化、动作呆板 | 需要多步迭代，计算量大 |

**为什么生成式更适合机器人动作**：人类示教的动作有丰富细节（避障、微调姿态）。
回归式模型会把所有示范「平均」成一个平庸动作；生成式模型能从分布中采样，
保留动作的多样性和自然度。代价就是需要「从噪声一步步洗出来」的迭代过程。

**流匹配的大白话原理**：

```text
x₀(纯噪声) --1: 预测速度 v₀--> x₁ --2--> x₂ --3--> x₃ --4--> x₄ --5--> x₅(≈真实动作)
                             每步：x_{t+1} = x_t + velocity × Δt（Euler 积分，Δt=0.2）
```

| 概念 | 大白话 |
|---|---|
| **x_t** | 当前动作候选（1×50×32）——t=0 是噪声，t=1 是最终动作 |
| **velocity** | 模型预测的「去噪方向」（1×50×32）——每步往真实动作挪多少 |
| **Δt** | 步长 = 1/5 = 0.2（5 步 Euler） |
| **关键** | 模型每步都重新参考 Prefix K/V（视觉+指令+状态的缓存），所以洗出来的动作始终朝「符合当前场景」的方向走 |

**denoise 内部结构**（项目文档 5.6 节，`denoise_origin.om` 约 401MB）：

| 部件 | 干什么（大白话） |
|---|---|
| action input projection | 把当前动作候选 x_t 转成模型内部维度 |
| timestep sinusoidal embedding | 把「当前走到第几步」编码成模型能读的形式 |
| time MLP | 融合时间信息，让模型知道这一步该激进还是保守 |
| 16 层 action expert | 核心 Transformer 网络，干「读条件 + 预测去噪方向」的活 |
| Prefix K/V 的 self/cross attention | 与语言前缀缓存交互——动作生成时反复参考上下文（KV cache 复用） |
| RMSNorm | 每层归一化，稳定训练和推理 |
| action output projection | 把内部表示投影回 50×32 动作空间 |

**项目真实数字**（面试数据弹药）：

| 项 | 数值 | 说明 |
|---|---|---|
| 单步去噪（NPU） | 56.95 ms | `denoise_origin.om` 单步延迟 |
| 10 步完整去噪 | ~1.14~1.37 s | 初版验证用 10 步 |
| 5 步完整去噪 | ~918 ms 整链 | 实机最终配置 |
| 数值精度 | 误差 ~1e-6 | ONNX vs 原生、OM vs CPU 全部对齐 |
| 最终动作误差 | ~0.043° | 反归一化后，几乎无损 |

**为什么 10 步改 5 步**：更多步 → 更细腻但更慢；5 步在 918ms 内完成且动作误差仅 0.043°，
精度足够。这是「质量 vs 延迟」的权衡（和 08 篇说的「先优化双缓冲而不是压缩模型」一致）。

**denoise 在完整推理链路中的位置**：

```text
vision.om (187ms)      → 图像变 token
state_proj.om (0.5ms)  → 关节状态变 token
prefix_origin.om (178ms) → 三者合流，KV prefill 一次（只算一次！）
denoise_origin.om ×5 (57ms×5) → 从噪声洗出 50×32（每步复用上面的 KV）
→ 输出投影 → 50×6 动作块（去归一化 + 限幅）→ 下发执行
```

**关键洞察**：denoise 每步都通过 cross-attention 读取 Prefix K/V——所以 prefix 只算一次，
denoise 5 步反复复用，这就是「KV cache 让推理快」的微观机制。

**面试追问延伸**：「去噪和扩散模型什么关系？」——流匹配是扩散模型的变体，
都是「加噪→学去噪」的生成范式，SmolVLA 用流匹配路线（LeRobot 0.6.1 实现），
特点是训练更稳定、步数可以更少。

## 4. 核心概念（大白话 + 面试版）

| 概念 | 大白话 | 面试怎么讲 |
|---|---|---|
| **模仿学习** | 看示范、学动作 | 从专家示教中学习策略（Behavior Cloning） |
| **ONNX** | 模型的通用交换格式，任何框架都能读 | 模型界的 JPEG，跨框架标准格式 |
| **检查点 (checkpoint)** | 训练到某一步保存的模型快照 | 020000 = 训练 2 万步的模型 |
| **流匹配去噪** | 从噪声逐步还原真实动作的过程 | 生成式动作建模，5 步 Euler 采样（详见 §3.5） |
| **20K steps** | 训练迭代了 2 万步 | 训练量配置 |
| **A100** | NVIDIA 数据中心 GPU（本项目的训练服务器） | 训练阶段算力平台（和部署端 NPU 不同） |
| **sim2real** | 仿真到真实的迁移（本项目未做） | 领域差距问题（后续可扩展方向） |

## 6. 踩过的坑（训练/模型侧）

| 坑 | 解决 |
|---|---|
| CPU 推理一帧要 73 秒，无法实机控制 | 必须部署到 NPU（模块 4） |
| 语言指令是「写死」的 48-token embedding | 改指令不会自动生效；支持新指令需动态 tokenizer（后续工作） |
| Transformers 动态视觉 mask 无法导出 | 固定 512×512、固定 position id、eager attention |
| BF16 权重被装进 FP32 骨架 | `load_state_dict(..., assign=True)` |

## 7. 面试怎么讲（1 分钟版）

> 模型选型上，我们用了 HuggingFace 的 SmolVLA——一个约 0.5B 参数的
> 视觉-语言-动作模型。选择它的核心考量是「能部署到边缘」：
> 它小到可以运行在昇腾 310B1 NPU 上，实测单次完整推理约 918 毫秒，
> 可以实时驱动机械臂。模型内部四个模块——视觉编码器、状态投影、
> 语言前缀、动作去噪器——也决定了我们后续的部署拆分策略。
> 动作生成采用流匹配去噪：从噪声出发 Euler 迭代 5 步，逐步还原出
> 50×6 动作块，每步都复用 Prefix 的 KV 缓存，单步约 57ms，
> 最终动作误差约 0.043°。训练采用模仿学习：50 段示教数据、20K 步，
> 产出 020000 检查点。语言指令通过固定的 48-token embedding 输入，
> 这是一处简化，支持任意自然语言指令需要动态 tokenizer，是我们的后续优化点。
