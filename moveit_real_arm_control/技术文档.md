## 1. 项目目标

在 PC（WSL）的 **RViz / MoveIt 面板**中规划轨迹，让 **SO-ARM101 真实机械臂**执行运动，形成完整闭环：

```text
WSL: RViz + move_group（规划）
   │  FollowJointTrajectory action（域42 + Zenoh）
   ▼
开发板: so101_command_bridge.py（action server → UDP）
   │  UDP 15001（目标关节，arm=度，gripper=percent）
   ▼
开发板: so101_command_executor.py（SO101Follower.send_action → 串口）
   ▼
SO-ARM101 从臂（真实运动）
```

同时保留只读遥测链路（机械臂 → `/joint_states` → RViz 实时显示）：

```text
SO-ARM101 从臂
   │  串口读取（executor 或 joint_source）
   ▼
UDP 15000 → so101_joint_bridge.py → /joint_states → Zenoh → WSL RViz
```

## 3. 系统架构与数据流

### 3.1 控制链路（下行）

```text
[PC/WSL] RViz MotionPlanning 面板
   │  Plan（OMPL 规划，URDF/SRDF 限位）
   ▼
[PC/WSL] move_group
   │  moveit_simple_controller_manager
   │  FollowJointTrajectory action（域42，经 Zenoh 到开发板）
   ▼
[开发板] so101_command_bridge.py
   │  /so101_arm_controller/follow_joint_trajectory
   │  /so101_gripper_controller/follow_joint_trajectory
   │  弧度 → 度（arm）/ percent（gripper）
   │  UDP 15001 单包下发（整条轨迹）
   ▼
[开发板] so101_command_executor.py
   │  多轨迹并发合并 → SO101Follower.send_action
   │  max_relative_target 限幅（10° / 20%）
   │  UDP 15002 回报 done/error
   ▼
[SO-ARM101] 从臂串口 → STS3215 舵机
```

### 3.2 遥测链路（上行）

```text
[SO-ARM101] → 串口（executor 或 joint_source 读取）
   → UDP 15000
   → so101_joint_bridge.py → /joint_states
   → Zenoh → WSL → robot_state_publisher → /tf → RViz
```

### 3.3 关键设计决策

1. **一个进程独占串口**：控制模式下 executor 同时承担遥测读取（UDP 15000）和命令写入（UDP 15001 接收），避免两个进程抢 `/dev/ttyACM1`。
2. **多轨迹并发**：MoveIt 把 arm（5 关节）和 gripper（1 关节）作为两条独立 `FollowJointTrajectory` action 发送；executor 按 seq 维护多轨迹字典，执行循环合并各轨迹目标到完整 6-DOF 状态。
3. **单位约定**：ROS/URDF 用弧度；LeRobot `send_action` 中 arm 用度（DEGREES）、gripper 用 0-100 percent（RANGE_0_100）；bridge 负责转换。
4. **安全三层**：
   - 规划层：URDF/SRDF 关节限位（MoveIt 规划时约束）；
   - 传输层：bridge 拒绝起始点距当前姿态 >45° 的轨迹；无当前状态时拒绝执行；
   - 执行层：executor `max_relative_target` 每调用限幅 10°/20%，硬限位校验（URDF 机械限位）。

## 4. 使用说明（从零启动）

### 4.1 前提

- 开发板 SSH：`root@192.168.0.2`（MobaXterm 或 `ssh -i C:\Users\98384\.ssh\codex_robot_arm_ed25519 root@192.168.0.2`）
- Follower 机械臂接电、USB 已插；工作区清空、人在旁
- PC 已配 WSL2 Ubuntu-22.04 + ROS2 Humble + VcXsrv（`F:\VcXsrv`）

### 4.2 开发板（MobaXterm）——一条命令

```bash
bash /root/lerobot_project/start_control_mode.sh
```

脚本自动完成：
1. 停只读桥（释放串口）
2. 启动 joint_bridge（UDP 15000 → /joint_states）
3. 启动 executor（连接 `/dev/ttyACM1`）
4. 开启运动门控（enable）
5. 验证 /joint_states

### 4.3 PC（PowerShell）——一条命令

```powershell
powershell -ExecutionPolicy Bypass -File F:\robot_arm_atlas\ros2\start_so101_real_arm.ps1
```

> ⚠️ 控制版用 `start_so101_real_arm.ps1`（带 move_group）；`start_so101_display_vcxsrv.ps1` 是纯显示版（只能看不能控制）。

### 4.4 RViz 操作

1. MotionPlanning 面板，规划组选 `arm`，Start State 选 `current`
2. 设目标：拖拽末端交互标记，或选命名姿态（`home`/`ready`）
3. `Plan` 预览紫色轨迹
4. `Plan & Execute` 执行真实运动
5. 夹爪：规划组切 `gripper`，目标 `open`/`closed`

### 4.5 停止与恢复

```bash
# 开发板：停止运动（保持扭矩，不坠落）
python3 -c "import socket,json;s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM);s.sendto(json.dumps({'cmd':'enable','on':False}).encode(),('127.0.0.1',15001))"

# 恢复只读模式
kill $(pgrep -f so101_command_executor.py) 2>/dev/null
kill $(pgrep -f so101_joint_bridge.py) 2>/dev/null
systemctl start so101-rviz-bridge.service
```

## 6. 故障排查速查表

| 现象 | 原因 | 解决 |
|---|---|---|
| RViz 机械臂残缺/报红 | `/joint_states` 无数据（只读桥或 joint_bridge 没跑） | `systemctl is-active so101-rviz-bridge.service`；或检查 `pgrep -f so101_joint_bridge`；`ros2 topic echo /joint_states --once` |
| Plan 可以但 Execute 不动 | ① executor 没跑 ② 运动门控关闭 ③ 硬限位拦截 | ① `pgrep -f so101_command_executor` ② 看日志 `motion gate -> ENABLED` ③ 看 executor 日志 `report ... error ... outside hard limits`，放宽限位 |
| executor 报 `There is no status packet` / `Port is in use` | 串口被只读桥或其他进程占用 | `systemctl stop so101-rviz-bridge.service` 后重启 executor |
| executor 报 `bad JSON` | UDP 包被 8192 截断（旧版） | 已修复为 `recvfrom(65507)`；确认部署了新版 |
| RViz 无法拖拽末端 | rviz2 未加载 kinematics 参数 | `real_arm.launch.py` 已传 `robot_description_kinematics`；确认 RViz 标题为 `moveit.rviz` |
| 轨迹被拒 `outside hard limits` | 硬限位与规划轨迹不符 | 硬限位已放宽为 URDF 机械限位（`moveit_real_arm_control/scripts/so101_command_executor.py`） |
| WSLg 窗口黑屏 | GPU-PV dxg 故障（需重启 Windows） | 用 VcXsrv 脚本绕过 |
| PowerShell `&&` 报错 | PS 5.1 不支持 `&&` | 用 `;` 或分行，或直接用 `start_so101_real_arm.ps1` |

## 7. 安全规则（必须遵守）

1. 实机运动前清空工作区，人在旁，随时准备 Ctrl+C 或断电；
2. 第一次运行先确认 `/joint_states` 有数据、机械臂模型完整；
3. 运动门控默认关闭，必须显式 enable（`start_control_mode.sh` 已自动做）；
4. `max_relative_target` 限幅 10°/20% 是最后防线，不要移除；
5. 只读桥和 executor **不能同时占用串口**；
6. 出现任何 NaN、跳变、异响立即 stop + 断电；
7. 网页/终端 `Ctrl+C` 正常退出时 executor 会断开并卸力——托住机械臂再操作。

## 8. 已知限制与后续工作

1. **硬限位**：executor 硬限位采用 URDF 机械限位（较宽）。若需更严格的任务级限位，可在 `ARM_LIMITS_DEG` 中按任务收紧。
2. **异步推理**：MoveIt 轨迹执行为同步等待；如需连续任务，可参考 `14_smolvla_atlas_live.py` 的动作队列思路做异步执行。
3. **executor 并发**：串口访问需保持单线程；当前主循环 + UDP 命令线程已分离，命令线程不碰串口。
4. **WSLg 恢复**：重启 Windows 后若 `dmesg -T | grep -i dxg` 干净，可直接 `source ~/ros2_humble_env.sh && ros2 launch so101_moveit_config real_arm.launch.py`，无需 VcXsrv。
